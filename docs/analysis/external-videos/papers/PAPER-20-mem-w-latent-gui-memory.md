## 核心机制（问题/方法/实验）

**问题**：GUI 智能体（操作 web/移动/桌面）的成败依赖携带视觉、程序性与任务级证据跨越当下屏幕。但多数智能体仍把记忆当作**外部、人类可读的产物**——历史被摘要、分类、检索、以文本或结构化记录重新注入，再由策略重新编码。这造成「经验存储的表示形态」与「现代 GUI 策略实际作用的隐式嵌入序列」之间的**失配（mismatch）**。

**方法（隐式记忆原生，Mem-W 系列）**：
1. **记忆进连续上下文**：把记忆当作智能体连续上下文的一部分，而非辅助符号脚手架。
2. **共享轨迹到隐式压缩器（trajectory-to-latent compressor）**：把**历史轨迹（经验记忆）与会话片段（工作记忆）**编织为紧凑的**记忆 token**。
3. **连续嵌入序列注入**：记忆 token 与当前 GUI 观察、局部上下文织入同一条连续嵌入序列——智能体通过同一机器原生接口读取成功、失败与未完成任务。
4. **训练**：自蒸馏（self-distillation）+ 结果感知监督（outcome-aware supervision）——保留决策相关状态，同时把记忆过滤向真正支撑任务成功的证据。

**实验**：4 个 web/移动导航基准，一致提升多样骨干与记忆增强基线，增益最高 **+30.0**（单位未明示）。

## 关键发现与数据

| 发现 | 数据（摘要原文） |
|:--|:--|
| **隐式记忆原生路线有效** | 记忆 token 织入连续嵌入序列；4 基准一致优于多样骨干与记忆增强基线 |
| **双流统一压缩** | 历史轨迹（经验）+ 会话片段（工作记忆）经**同一压缩器**→记忆 token |
| **结果感知监督** | 自蒸馏 + outcome-aware 监督——过滤记忆向「真正支撑任务成功」的证据 |
| **增益** | 最高 +30.0（量纲未明示，未验证） |

**限制（摘要/分析明示）**：① 「+30.0」单位/口径未明示（未验证）；② 隐式记忆 token **不可读、不可审计**（与 PAPER-13 MemGen 同族）；③ 主模型为小骨干 + 需训练（与 Kairos 免训练架构定位不同）；④ 压缩器的信息损失行为未在摘要讨论。

**重点回答**：与 Kairos 直接对话的是**双模式 Compaction（§5.2）与可审计性红线（§1.7/§5.5）**。论文价值：① 隐式记忆 token 形态不可审计——不采纳（与 PAPER-13 MemGen 同族矛盾记录）；② 「统一压缩器编织经验+工作记忆」双流压缩是 Compaction 设计参考（须 P6 门禁）；③ 结果感知过滤与 Kairos 认知真实性立场张力（同 PAPER-19 决策效用张力）。

## 可吸收增量（具体到机制/参数/设计）

1. **双流统一压缩参考（评估注记）**：双模式 Compaction（§5.2）补充注记——「历史轨迹 + 会话片段经同一压缩器」的双流统一压缩设计（Mem-W，同组 G-Memory 系列）作为 Compaction 候选形态；须过 P6 门禁（可重建校验 + 无无声维度丢失 + 差异检验）。
2. **「不可审计记忆形态」矛盾记录（红线注记）**：架构 §1.7 监督平面/安全红线（§8）注记——Mem-W 记忆 token（隐式、不可读）与可审计性红线冲突；与 PAPER-13 MemGen 同族并案记录（本批次 2 篇 latent 路线论文均不采纳存储形态）。
3. **结果感知过滤张力记录（张力注记）**：蓝图 §5.3 价值独立性公理注记——「过滤记忆向任务成功证据」与 Kairos 认知真实性张力（并入 PAPER-19 决策效用张力记录）；使用侧热度承载效用面，过滤决策不入真实性裁决。
