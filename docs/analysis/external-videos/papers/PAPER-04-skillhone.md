## 核心机制（问题/方法/实验）

**问题**：优化历史丢失（optimization history loss）。Agent 技能会因环境变动（搜索接口限流、API 改版、网页结构变化）失效；既有方法在受限轮次内改进技能后只保留最终产物，丢弃了诊断、被否候选、评估证据与结果——下一轮接手的 Agent 不知道「当初为什么改、试过什么失败方案、上一轮回退了什么」，只能重复已失败的探索。

**方法**：把「优化过程本身」建模为一等对象。

1. **持久决策历史**：每个优化步骤记录为结构化历史条目——**问题诊断 / 候选修订 / 脱敏后的评估证据 / 最终结果**（接受/继续修改/拒绝）。后续 Agent 可审计先前变更、理解改动原因、避免重复编辑、跨会话延续开发。
2. **双仓库架构**：技能仓库（`SKILL.md` + 脚本 + 参考资料 + 模板，技能视为完整 repo 而非单个 md 文件）+ 技能评估仓库（练习探针、标准答案 oracle、验证器、溯源元数据、执行轨迹、回归测试）。
3. **角色分离子智能体 + 权限边界**：优化侧（Proposer/Explorer/Developer/Reviewer/Decider）可写技能仓库，但**看不到未脱敏的评估答案、验证器或轨迹**；评估侧（Executor/Diagnoser/Reporter/Auditor）可检视探针与轨迹，但**不能写技能仓库**、无修订决策权。运行时调度器按需创建权限受限的团队，只向优化侧返回**脱敏报告**（失败模式、汇总结果、诊断假设）——结构性防止对评估资产的过拟合与泄露。与运行时解耦，可接入 Claude Code / Codex / Hermes。
4. **Repo 级更新**：可同时修改脚本与辅助文件（SkillOpt、Hermes-SE 仅优化 `SKILL.md` 文本）。
5. **范围性回滚（scoped reverts）**：性能回退时通过定向后续编辑恢复，保留候选版本中仍有效的改动（非整体接受/拒绝整个 prompt 候选）。

**实验**：深度研究基准（原始开放网络、无预集成搜索栈）+ 7 个内部工具介导分析场景 + 消融（决策历史 vs 角色分离）+ 跨骨干迁移。

## 关键发现与数据

| 指标 | 结果 |
|:--|:--|
| GAIA | 超商业检索支持的深度研究智能体 **15.8 分** |
| WebWalkerQA-EN | 超商业深度研究智能体 **3.2 分** |
| 内部工具介导分析（7 场景） | 平均准确率提升 **18.8 个百分点**（6/7 场景优于种子技能） |
| 消融 | **决策历史的贡献大于角色分离** |
| 优化轨迹示例 | 30% → 70%，从两次退化修订中恢复（scoped reverts）；Hermes-SE 在标量验证信号下只能整体接受/跳过 |
| 迁移性 | 演化后的技能包可迁移到不同执行骨干（如 Claude Sonnet 4.6）无需再优化——收益来自技能程序本身而非特定模型 |

**局限**：仅英语基准；仅单技能独立进化，未处理多技能相互依赖（共享资源、重叠失败模式）的联合进化。

## 与 Kairos 的映射点

**直接对话机制**：Kairos 的决策编号与决策追因（[adr.md](../../../governance/adr.md) D-01~D-27）、见证锚定+差异检验（[架构](../../../foundation/architecture-v0.1.0.md) §5.5）、语境自指禁令 S-14、升华管道（[认知基础](../../../foundation/cognitive-foundation.md) §1.10）。外部实证**支撑** Kairos 的价值独立性公理与认知完整性轴，同时提示「过程记忆（决策历史）」是 Kairos 未显式建模的记忆类型增量。

## 可吸收增量（具体到机制/参数/设计）

1. **决策历史条目格式**：将 [adr.md](../../../governance/adr.md) 的决策追因升级为四元组结构「诊断/修订/脱敏证据/结果」，evidence 字段指向见证锚定副本——落点：策略层程序记忆（[架构](../../../foundation/architecture-v0.1.0.md) §3.2）与意图契约（§3.7）扩展。
2. **范围性回滚粒度**：Kairos 差异检验 11 步（blocked→degraded→pruned→rollback，[架构](../../../foundation/architecture-v0.1.0.md) §5.5）的 rollback 步骤增强为「按变更单元回滚、保留候选中的有效改动」，而非整条记忆回退。
3. **评估资产访问边界**：在监督平面/审计庭（[架构](../../../foundation/architecture-v0.1.0.md) §1.7）增加「评估资产读写分离」机制：评估侧（oracle/验证器）不可写主副本、优化侧不可见未脱敏评估数据——与 S-14 语境自指禁令同族。
4. **消融实验设计**：以「机制贡献 vs 记忆贡献」消融作为 Kairos 待证伪假设（H1/H2）的验证模板。
5. **技能仓库级更新**：升华管道 strategy/behavior 落地单元参考——技能=repo（指令+脚本+模板）而非单文档，与「契约是运行时投影」的软约束一致。
