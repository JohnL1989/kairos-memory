## 核心机制（问题/方法/实验）

**问题（黑盒遗忘审计）**：机器遗忘（GDPR「被遗忘权」、AI 安全、模型质量）声称模型已"忘记"特定训练数据，但审计者通常**黑盒操作**——无法访问模型内部、权重、原始训练数据，只能通过查询模型、分析输出样本验证，这构成**两样本检验**问题：遗忘模型的输出分布 vs 基准分布是否可区分？

**既有工具的缺陷**：
- **MMD（最大均值差异）**：在大规模模型上统计功效不足，需不切实际的大样本量；擅长检出全局/广域偏移，但会漏掉**高度局部的异常**（仅被极特定 prompt 触发的离群输出）。
- **已知假阳性缺陷**：同一数据不同 batch size 从头重训的两个模型分布不同——标准两样本检验会把「训练配置差异」误判为「未遗忘」，产生假阳性。
- **理论下界**：先前工作（arXiv:2510.16629，2025-10）证明模型**仅调参数不可能完美遗忘**——参数脚印永久残留，完美「重训等价」对标准局部遗忘算法根本不可能。

**新框架（三样本相对检验 + 正则化 f-散度族）**：
1. **三样本相对检验**：不把遗忘模型与「从头重训」直接对比，而是测遗忘模型**分布上更接近「安全重训模型」还是「原始有缺陷模型」**——把绝对断言降级为相对断言。
2. **f-散度族按偏移类型选型**：卡方（chi-squared）与 KL 散度——适合平滑、局部差异（如物理模型的离群值）；**hockey-stick 散度**——专门捕捉隐私/遗忘定义，其参数控制统计不可区分程度，设定「安全预算」阈值、忽略预算内的小差异。
3. **核正则化**：使高维真实数据上的散度估计可计算，无需海量算力。
4. **自动超参选择**：自动挑选最有信息量的散度及最优核带宽、正则参数——避免人工配置误差。
5. **理论保证**：**任意样本量下控制假阳性（Type I error）**；假阴性风险随样本量增加收敛到零。

**实验**：SVT3（稀疏向量技术差分隐私机制）违规检出；TOFU 数据集 + 既有移除方法（RMU 等）基准。

## 关键发现与数据

| 发现 | 数据（第三方解读口径，未验证） |
|:--|:--|
| **样本效率大幅提升** | SVT3 上仅需**数千样本**即可检出违规，而 Google 2024 参考工具 DP-Auditorium（arXiv:2307.05608）同类检出率需**数百万**样本；hockey-stick 变体在稀疏向量方法上以数千样本检出隐私违规 |
| **假阳性可控** | 框架对任意样本量给出 Type I error 控制保证（理论性质） |
| **基准方法多被判定「未擦除」** | 论文简化实验条件下，**Selective Synaptic Dampening（SSD）、剪枝、微调均被判定无法有效擦除目标数据**；仅 random label 技术通过三样本相对检验——作者承认此为本框架的局限（门槛严苛） |
| **可验证的遗忘成为可测属性** | 把遗忘从政策承诺变为「带数据集谱系、训练快照、评估 prompt 与验收阈值的假设检验问题」 |

**限制（论文/解读明示）**：**尚未在 LLM 上验证**——已发布验证仅覆盖合成基准与高能物理数据集，而 LLM 恰是数据删除监管争论的中心；增益仅在 SVT3 上记录，作者注明**没有单一散度系统性占优**；检验只能确认「相对基准对的遗忘有效性」、**永远不能证明数据绝对消失**（呼应「完美遗忘不可能」定理）；未与 Chen 等（LMU Munich/Oxford/Siemens）的 LLM 专用审计框架对比。

## 与 Kairos 的映射点

| 外部理念 | 分诊（初步） | Kairos 证据 | 第一性原理评估 | 备注 |
|:--|:--|:--|:--|:--|

| 「完美遗忘不可能（参数脚印永久残留）」 | 张力（层级边界声明） | [安全规格](../../../security/security-specification.md) S-19 哈希净化「原文不可逆」；[架构](../../../foundation/architecture-v0.1.0.md) §8 | 挑战/提示：定理针对**模型参数**（调参数无法擦除脚印）；Kairos 是**系统层存储**——数据级删除（S-19）可达成，但「行为脚印」仍可能残留（检索候选排序痕迹、cross-encoder 重排偏置） | 需在 S-19 规格中声明边界：内容不可恢复 ≠ 行为完全无痕；「行为残留」作为可观测例外登记（呼应 §5.5 分级触发理念） |
| 「任意样本量下假阳性可控 + 假阴性随样本收敛」 | 可吸收 | [测试策略](../../../quality/test-strategy.md) §2.2 安全红线验收表（S-16/S-19 逐条验证）；[质量门禁](../../../quality/acceptance-criteria.md) | 支撑：可作为「遗忘后残差验证」的统计门禁口径——遗忘验证从「查 DB 确认哈希替换」升级为「行为级两样本检验 + 样本量-功效权衡」 | 映射分析建议：遗忘后残差验证纳入质量门禁指标 |
| 「黑盒审计者视角」 | 张力（白盒 vs 黑盒） | [架构](../../../foundation/architecture-v0.1.0.md) §1.7 监督平面（审计庭，HMAC 审计链，白盒）；[威胁模型](../../../security/threat-model.md) Repudiation | 提示：Kairos 审计庭是**白盒**（自有审计日志 + content_hash 可验证），可用更强断言；黑盒统计框架是「外部审计者视角」补充 | 呼应用户侧「外部审计 78 项问题」教训——Kairos 自审计再完备，外部黑盒视角仍是独立校验层 |
| 「hockey-stick 散度的安全预算参数」 | 可吸收 | [架构](../../../foundation/architecture-v0.1.0.md) §5.5 差异检验分级触发（低/高风险场景分级） | 支撑：「安全预算下的小差异可忽略」与 Kairos「良性正相关标记降低检验频率」同构——散度阈值即分级阈值 | 可借用「预算阈值显式化」改进 §5.5 分级条件表述 |

**重点回答**：与 Kairos 直接对话的是**「审计完备的带权文件系统」定位 + 双副本遗忘验证**。论文价值：① 提供**三样本相对检验**范式——遗忘验证不必证明绝对消失，只需证明「更接近从未见过基准」；② **实证警告**——SSD/剪枝/微调等抑制型遗忘在相对检验下「不通过」，只有彻底改写（random label）通过：对 Kairos 的含义是**可逆抑制（§5.2 标记抑制）未必满足「遗忘生效」的统计断言**，S-19 不可逆净化才接近「通过」。

## 可吸收增量（具体到机制/参数/设计）
1. **遗忘生效的三样本检验**：定向遗忘（含 S-19 净化）后运行行为级验证——遗忘模型输出分布 vs「从未见过该记忆」基准 vs「未遗忘」基线，判据为更接近前者；纳入质量门禁指标（[验收标准](../../../quality/acceptance-criteria.md) D-304 扩展项）。验证方法：预登记评估 prompt 集（黑盒查询，无内部依赖）。
2. **双副本遗忘完备性测试用例**：新增测试——仅净化主副本、影子副本仍含使用权重时，检索不得命中（三信号混合检索 [架构](../../../foundation/architecture-v0.1.0.md) §7.3a 融合链路须在任一副本残留时产生可检差异）。
3. **S-19 边界声明（行为残留）**：在 S-19 规格中显式区分「内容不可恢复（已满足）」与「行为无痕（不可承诺）」；行为残留作为观测项交给审计庭（§1.7）定期报告。
4. **差异检验分级阈值参数化**：借鉴 hockey-stick「安全预算」——把 §5.5 差异检验的「低/高风险场景」触发阈值显式化为可配置的统计预算参数（如可忽略的散度差上界），消除「<50ms 快速检验」与「完整检验」的模糊边界。
5. **外部审计演练**：以黑盒视角对审计日志进行抽查比对（白盒审计的独立校验层），作为审计庭季度演练项。
