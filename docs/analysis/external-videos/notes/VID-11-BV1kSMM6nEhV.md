## 内容提炼
### 核心论点
1. 记忆系统的常见失败模式：「记了不查、查了不用」——Agent 写 0.84 次记忆才查一次（write/search 比 0.84），几乎只写不读（00:13）
2. 核心洞察：记忆不是存储模块，是认知技能——知道记什么、何时查、怎么组织；「先查后写」是训练出来的，不是天生的（01:57 / 01:25）
3. 元记忆概念：你不仅靠记忆本身，还靠一套关于记忆的策略——什么时候该记、记什么、怎么整理；人类天然有元记忆（考试前该背什么），但 LLM 没有这个能力（02:06）
4. 记忆能力可以训练：AutoMEM 用双循环优化框架（脚手架结构优化 + 模型熟练度训练），仅优化记忆、不改任务能力，32B 模型在 miniHack 上 30% 超越 Claude Opus 4.5 的 27.5%，三个环境性能提升 2~4 倍（03:16）
5. 五个诊断信号：文件膨胀（无界追加）、写了不查（write/search 高）、策略僵化（手工调不动）、上下文溢出（记忆文件挤占推理空间）、延迟后果（第 5 步不忘、第 800 步才迷路）——分别对应 Upsert 去重、LoRA 微调、MetaLLM 自动迭代、按需检索、全轨迹审查+门控（06:11 / 06:46 / 06:51）

### 关键机制
- AutoMEM 双循环架构：内循环 agent 执行任务；外循环一优化记忆脚手架（结构层），外循环二训练记忆能力（模型层）；两个循环顺序执行（02:29 / 03:16）
- 记忆动作与任务动作在同一动作空间：read/write/search/append/create 由同一次前向传播选择，每个记忆决策都是可追踪的动作；AutoMEM 新增 UpsertMap 坐标去重（02:32 / 02:47）
- 外循环一（脚手架迭代）四步：运行 episode → MetaLLM 审查完整轨迹（诊断整段失败）→ 修改脚手架 → 门控验证（修改后在固定种子上重跑，平均进展改善才保留；失败重试一次，仍失败重启）（03:40）
- 脚手架迭代实例：v0 初始（无界追加地图）→ v1 MetaLLM 发现地图膨胀、引入 Upsert 去重、精简日志、预填充策略文件 → v2 发现 agent 迷路和重复移动、加入自动状态维护和来回移动警告——两轮收敛，实践中 2~5 轮收敛（04:05）
- 外循环二（记忆熟练度训练）三阶段：收集轨迹池 → MetaLLM 推导选择标准、筛选优质决策 → LoRA 微调；关键设计：训练数据是 agent 自己产生的文本，MetaLLM 只做过滤器不生成新内容；纯游戏动作被过滤，只保留记忆操作推理（04:47 / 05:04 / 05:11）
- 训练数据规模很小但很精：crafter 1597 条、miniHack 444 条、nethack 800 条（05:15）
- 训练后行为变化：write/search 比降 54%、非生产性动作降 32%、冗余写入降 68%、每步上下文缩减 25%（05:24）
- 部署双模型：记忆专家处理记忆操作、游戏模型提交任务动作，共享对话历史（05:52）
- 论文自陈局限：仅游戏环境验证、每环境独立优化、短期记忆每 episode 重置、跨环境共享与真实世界适用性未验证（06:00）

### 可操作细节
- 坑一解法：UpsertMap 覆盖式更新，地图文件每步从 138 字符降到 6 字符（降幅 95%）（01:03）
- 坑二解法：LoRA 微调后 write/search 比从 0.84 降到 0.39（01:25）
- 门控验证：固定种子重跑 + 平均进展改善才保留（03:58）
- 五个信号速查清单（截图级资产）：膨胀→去重；写了不查→微调；策略僵化→自动审查迭代；上下文溢出→按需检索；延迟后果→全轨迹审查+门控（07:01）

## 存疑与未验证
- 视频转写错字较多：「UpsertMap」音译为「适应入upster/upside去种/Ultramanlight」、AutoMEM 拼写不确定、Metallel/Metallium（MetaLLM）等，均以英文语义推测还原（未验证）
- 性能数字（32B 30% vs Opus 4.5 的 27.5%、2~4 倍提升、0.84→0.39、138→6 字符）为 UP 主转述论文数据，未与原文核对（未验证）
- 论文出处未给出（视频只提「斯坦福 AutoMEM」），无法检索原文（未验证）
- 「五个信号」为 UP 主自创的总结框架，非论文内容（未验证）
