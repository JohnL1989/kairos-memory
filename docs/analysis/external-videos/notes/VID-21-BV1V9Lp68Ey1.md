## 内容提炼
### 核心论点
1. 腾讯开源 Agent Memory 的记忆理念：「不是为了让 AI 存下所有东西，而是为了让人不必重复所有的事情」（00:58-01:10）。
2. 结构化存储优先：把用户画像、memory 画布等细节以结构化形式存进 SQLite，而不是放进 markdown 格式——markdown 太长会拖累上下文，SQLite 可以通过关键词检索数据，「非结构化的数据跟结构化的数据比起来效率还是差很多」（01:28-02:06）。
3. 自动化记忆（自动挡）对比手动提醒（手动挡）：每次对话结束后自动提取关键信息存进 SQLite，自动召回相关记忆并自动去重，每五次对话自动评判当前人格——而 Claude 的 memory 需要用户提醒才去记，不提醒就不会主动开启（02:09-02:51）。
4. 本地存储+可迁移性：SQLite 数据库文件备份拷贝到任意地方随时可以启用、终身跟随，用网盘备份即可；而线上 memory 有两个问题——信息泄露风险（很多人不想把自己的信息泄出去）与成本（现在免费最终都要收费）（04:35-05:06）。

### 关键机制
- 分层记忆结构：把随便的对话转换成结构化的资产，再通过场景认知做一个服务画像（01:04-01:21）。
- token 节省效果：官方称接入后能节省 61% token，即使按保守估计省 30% 也「血赚」——因为完全免费、上手门槛极低（00:40-00:55）。
- 安装极简：一条命令复制给 Claude 自动完成安装；功能自动生效——每次对话后自动提取关键信息、自动解释相关记忆、自动去重、每次最多提取 20 条记忆、每五次对话自动评判人格（02:06-02:36）。
- 当前默认配置：自动补货、召回、提取全开；每五次对话触发一次 L2 级的处理（人格评判，被分三份）；目前没开清理记忆，不需要配置直接用（02:51-03:07）。
- 技术选型动机：SQLite 是微信的底层存储，腾讯有非常丰富的经验（「微信用几年都不带卡」）；把 SQLite 经验搬到智能体 memory 上是很好的选择（04:11-04:35）。
- token 成本背景：现在 Agent 的调用量比纯对话翻了几倍到几十倍几百倍，「token 变贵的时候就要考虑怎么节省」，此类项目会越来越多、越简单越好（03:22-04:15）。

### 可操作细节
- 安装：把官方安装命令复制给 Claude 让它自动安装，无需手动配置（02:06-02:16）。
- 默认配置可直接用（提取/召回/补货全开，每 5 次对话 L2 处理），无需调整（02:51-03:07）。
- 备份迁移：把 SQLite 文件拷贝/网盘备份即可随时启用、终身跟随（05:02-05:06）。
