## 内容提炼
### 核心论点
1. 给 agent 接 memory 别先问有没有向量库，先问状态能不能留下来：试试会话结束后状态还在不在、经验能不能更新、能不能变成技能（00:00-00:15）。
2. 长期记忆如果只进不出，很快会变成杂物间——系统越来越慢、越来越容易召回低价值内容；PowerMemory 用大模型参与记忆的抽取、更新和合并，并结合艾宾浩斯时间衰减调整记忆优先级（01:43-02:13）。
3. 时间衰减不等于粗暴删除：「明确过期」「仍然有效」「很久没用」是三种不同状态；如果系统把三种状态混成一种，要么忘得太狠，要么旧事一直复活（02:13-02:26）。
4. 经验要变成会做的事：experience 保存从交互中提炼的经验，skill 把反复验证的经验整理成可复用做法（两层蒸馏，对应程序性记忆）；迁移案例要留下前置检查、执行步骤、验证方式、回滚条件，历史才是能直接影响行动的参考（02:28-02:52）。
5. 判断一个长期运行的 agent，不要只问有没有存聊天记录、有没有向量库，要问六个工程问题：会话结束后状态还在吗？历史是不是只有向量一种查法？旧事实能不能更新？低价值内容会不会退场？成功经验能不能变成技能？多个应用能不能共用同一套记忆底座？（03:43-04:10）

### 关键机制
- PowerMemory（OceanBase 开源的 AI memory 系统）：要做的不是把聊天记录堆进仓库，而是把对话、行动和反馈整理成长期可用的状态；提供持久化记忆、用户画像和作用域管理——按用户和 agent 隔离，也能在需要时共享，模型可以换、会话可以重开，用户偏好和任务进度不用陪着上下文一起下班（00:27-01:13）。
- 同一份历史多种查法（对应前集 views 概念）：向量检索擅长找意思相近的内容、全文检索擅长查名字和编号、图检索擅长查关系、新进度信号负责提醒刚发生的变化不被旧记忆淹没；把所有问题都交给一种检索方式「像拿一把螺丝刀装修整套房」（01:13-01:42）。
- Memory OS 五模块总纲：「ledger 管真相、views 管可用、policy 管控制、bridge 管注入、skill 管复用」（04:15-04:26）。
- 上下文桥（Context Bridge）：提供 Python SDK、HTTP 服务、MCP、CLI 等不同入口访问同一套后端；应用可以换记忆不用反复搬家，接入记忆内容仍由后端统一管理，避免每个应用发明一种私有记忆格式（02:55-03:24）。

### 可操作细节
- 衰减策略示例：新地址可以更新旧地址；反复出现的工作偏好可以逐渐变成稳定画像；长期不用的零碎信息推到后排，但不是删除（02:04-02:13）。
- 部署路径：支持 OceanBase、嵌入式、PostgreSQL、SQLite 等；本地实验可以轻量开始，长期服务再换更适合持续运行的数据库，Memory OS 上层抽象不用推倒重来（03:25-03:42）。
- 演进方向预告：更细的 ledger 回放、更自然的双时态查询、能从真实反馈中调整的 policy、更高效的浅层记忆注入（04:31-04:37）。
