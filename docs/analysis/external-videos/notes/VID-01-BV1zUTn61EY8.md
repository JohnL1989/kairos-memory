## 内容提炼
### 核心论点
1. 记忆 ≠ 长上下文，也不等于检索增强；判断谁是「真记忆」要看是否把「分层、写回、遗忘、治理」做成引擎，还是只存一份用户画像（00:25-00:40）。
2. 六刀标尺评价记忆引擎：①记忆纵深（只记用户画像还是做到情节记忆、程序记忆）；②检索召回（该记的取不取得回）；③写回治理（会不会更新、去重、遗忘、过期，防止记忆越用越脏）；④可搬可迁移（开源是真开源还是半开源，记忆能不能倒出带走）；⑤工程就绪（能否上生产）；⑥生态集成（00:57-01:38）。
3. 第一名 ZAP（开源核心 GRAPHITY）：把记忆做成「会计时间的知识图谱」——谁在什么时候说了什么、哪条事实什么时候失效都记在图上；「双实态知识图谱」旧事实不删除、指标记继承、从某时间起失效，天然治了记忆的更新冲突和污染（05:46-06:12）。
4. 记忆引擎（给 Agent 装的后端）与第二大脑（给人/组织用的工具）是两个物种，不应混为一谈；Engine 负责让 Agent 记住状态，第二大脑负责帮人沉淀资料（07:17-07:45）。

### 关键机制
- 六刀标尺下各家评分分布：第七名 Lane Mam（纵深3/召回3/治理2/可搬4/就绪2/生态4）——半成品零件，存储要自己接、抽取更新要自己拼提示词，绑死图生态（01:42-02:19）；第六名 Memobase（纵深2/召回3/治理3/可搬4/就绪5/生态2）——不用向量库，只把用户聊出来的压成结构化画像，取回 80 毫秒，记忆最浅但最诚实（02:20-02:59）；第五名 Supermemory（纵深3/召回3/治理3/可搬3/就绪4/生态4）——记忆/检索/画像/连接器全塞一个盒子，什么都会一点但没一样最深（03:02-03:32）；第四名 TencentDB AgentMemory（纵深4/召回3/治理4/可搬4/就绪3/生态3）——MIT 协议，短期记忆把工具调用日志压缩成轻量 Memory 结构符号，官方称 Token 最多省 6 成（03:34-04:17）。
- 第三名 Letta（MemGPT 正统续作）：记忆分核心/召回/归档三层；Agent 会自己改自己的记忆，还在往「记忆原生强化学习」走；但它是整个 Agent 运行时，想用其记忆基本要把整个 Agent 搬进它的框里跑，外挂使用者嫌重嫌锁（04:18-04:59）。
- 第二名 Mem-0：近五万颗星、两千多万美元融资；2026 年四月第三代算法——增量抽取、混合检索、实体链接；开源阉割小尾巴：自部署 Python 版能用图记忆，官方 NPM 包把图记忆锁在云端付费模式（05:00-05:45）。
- 第一名 ZAP：图跑在 Neo4j 上，不算轻；开源的是 GRAPHITY，好用的 ZAP Cloud 是闭源的（05:46-06:32）。
- 选型结论：要最强治理、扛得住知识图谱工程看 ZAP；要通用、好接、社区大选 Mem-0；从零搭有状态 Agent 用 Letta；中间各家各有取舍，越往下越轻越专（06:32-07:00）。

### 可操作细节
- 用六刀标尺（纵深/召回/治理/可搬/就绪/生态）逐项给候选记忆引擎打分再选型（00:57-01:38）。
- 识别「半成品引擎」的信号：存储要自己接、抽取更新要自己拼提示词、绑定单一生态（01:42-02:19）。
- 注意开源阉割：同一产品不同发行渠道（Python 包 vs NPM 包）能力可能不一致，图记忆可能锁云端付费（05:00-05:45）。
- 不要把记忆引擎与第二大脑（如 COSHA、BASIC MEMORY、DryBrain）混着比（07:17-07:45）。
