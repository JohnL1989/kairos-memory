## 内容提炼
### 核心论点
1. 三个概念必须分开：**会话**（一次独立聊天的完整交流史）、**上下文**（模型每次回答前真正拿到的全部信息：对话、系统要求、工具结果、临时读入文件——容量有限、随轮次变化）、**长期记忆**（会话之外保存、需要时召回重新注入的信息）；「当前回答主要靠上下文，跨会话的连续性要靠长期记忆的写入和召回」（01:32-02:41、03:45）。
2. 决定记什么看两个维度：**有效多久**（本次会话有效 / 长期但会变化 / 长期稳定直到明确更新）× **内容是什么**（事实：关于人或世界 / 经历：发生过的事情 / 方法：反复验证过的做事方式）；「以后看到任何一条 AI 记忆只问两个问题：它记得是什么、它应该有效多久」（04:11-05:29）。
3. OpenClaw（组织模型/工具/文件/记忆的框架，不是大模型本身）的智能体生命周期：新窗口「醒来」读身份与规则文件 → 召回相关长期记忆 → 工作（工具调用）→ 把值得保留的变化写入当日记录 → 上下文膨胀后压缩 → 空闲时 dreaming 整理，不断循环（05:36-09:00）。
4. 记忆落盘（memory flash，解决「以后还能不能找到」）与上下文压缩（compression，解决「上下文太大装不下」）是两个不同的动作，不能混淆；压缩后的摘要不自动等于长期记忆，仍要模型判断有无长期存在价值才送进档案室（11:12-12:25）。
5. Dreaming 不是模型突然有了意识，而是凌晨自动运行的离线记忆整理程序（默认关闭，开启后默认每天凌晨三点跑一轮），三步：浅睡眠扫描 → REM 把零散事件串成主题做反思 → 深睡眠判断哪些值得长期保留（12:29-14:19）。
6. 判断一个记忆系统好不好不能只问「存了吗」，至少要看五件事：**写得对、找得到、用得准、改得动、忘得掉**；markdown 方案透明可读、可修改、出问题容易查，但写入/召回质量依赖大模型本身、文件变多后找内容变难、跨环境/多智能体共享不存在（15:29-16:18）。

### 关键机制
- 会议室比喻：会话=会议室，上下文=桌上正在使用的资料，长期记忆=外面的档案室按需调档；「只存不取就是档案在但没想起来」，存下来却没有召回对此刻的模型仍然等于不知道（02:41-03:22）。
- OpenClaw 启动文件分工：`Soul.md`（智能体是谁：身份/人格/长期行为原则）、`User.md`（为谁服务：用户的稳定信息与偏好）、`Agents.md`（怎么工作：规则边界、什么能说什么能记什么不能记）、`memory.md`（经过筛选值得长期保留的记忆）+ 按日期编号的每日记忆文件（保存当天重要事实、事件、决定与变化）（06:12-07:40）。
- 上下文压缩：模型一次能读的内容有容量上限也有成本；OpenClaw 在上下文接近容量预算时把较早的对话整理成更短摘要，保留最近内容和当前任务状态，过长的旧原文/工具结果被裁剪——「把 50 页一小时的内容压成一页会议纪要」（09:30-10:50）。
- Dreaming 的产物：达到标准的内容自动写进 `memory.md`；本轮整理过程写进 `dreams.md`，留下一份人能看懂的「梦境日记」；整理不是写日记式的记录，而是记忆内容变化更新、时间新鲜度下降的再整理（12:51-13:49）。

### 可操作细节
- 容量现实：DeepSeek V4 Flash、GPT-5.6 宣称 1M 上下文，但 codex 订阅实际只有约 372K，API 按量付费才有一兆；处理几个文档/文件很快就会达到上限（09:39-10:28）。
- 生命周期一线概括：「醒来读规则，召回一部分长期记忆，开始工作，工作完写入长期记忆，上下文不断膨胀，然后压缩整理，新开窗口再醒来」（08:39-09:00）。
- dreaming 参数：默认关闭；开启后默认每天凌晨三点自动运行一轮（12:37-12:43）。
- 局限清单：写入和召回质量依赖智能体本身（大模型靠不靠谱）；文件变多后找相关内容变难；换机器、跨环境、多个智能体共享都不存在，还需继续解决同步、权限和冲突问题（15:38-16:10）。
