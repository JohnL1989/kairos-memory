## 内容提炼
### 核心论点
1. 大模型本身不记事，「你觉得他记得你」是产品在模型外搭的记忆系统，记忆能塞多少被上下文窗口卡死（00:41）
2. 长期记忆要解决四道难题：容量、成本、捞得准、会更新（信息会变会自相矛盾，好的记忆得会更新）（01:09）
3. 记忆存储的五种形式：流水账（向量相似）、关系网（知识图谱多跳）、带时间线的关系网（事实标生效/作废时间）、人物卡（字段化用户画像）、操作系统式分页（AI 自己调进调出）（01:49）
4. 记忆框架两大物种：外置记忆挂件（Mem0 夹在 AI 与数据库之间自动抽事实）vs 自带记忆的 AI 本体（Letta 自己判断哪条写常驻、哪条归档）（02:22）
5. 评测罗生门：各家自测自评不可信——Zep 同一评测三个数字（84%→58%→75%），Mem0 论文自打 68 分，第三方发现硬塞全部历史也能拿 73%，比部分优化框架还高（05:15）

### 关键机制
- 四道难题的分解口径：容量强（窗口就那么大）、成本强（塞更多历史又贵又慢）、捞得准（存得下不等于找得准）、会更新（旧事实作废、新事实生效）（01:15-01:43）
- 五种记忆形式的取舍：时间线关系网（Zep）不删旧事实，只给旧的打「已失效」、新的打「现在生效」，支持查历史时点状态（02:03 / 03:29-03:53）
- 评测缺陷盘点：自测自评、实现错误（把对话双方标成同一个人、并行检索做成串行导致延迟虚高）、评测对话仅一两万字落在当前模型窗口内，「长期」含金量存疑（05:49-06:36）
- 选型对号入座：加装记忆看 Mem0；从零做长期自进化 agent 看 Letta；事实随时间变且要查历史看 Zep；跨文档推理看 Cognify；C 端记住你是谁看 Memobase；编程助手失忆看 Agent Memory（07:07-07:30）

### 可操作细节
- 挑工具原则：看到「准确率提升 X%、省 X% token」先问「谁测的」——自己测自己赢几乎无信息量，只有第三方独立复现、交叉验证过的数字才值得当真（06:42）
- 星星多不等于能上生产（那是关注度不是稳定性）；榜单成绩不等于你的真实场景（合成对话 vs 企业知识每月变化+用户档案隔离）（07:37-07:57）
- 最终建议：拿自己的数据把候选框架各比一遍（07:59）；选型本质是选你愿意承受哪一种代价（08:20）
