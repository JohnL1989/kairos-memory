## 内容提炼
### 核心论点
1. agent-memory 项目（GitHub 约 9K 星）解决「AI agent 经常失忆」问题：昨天讲过项目启动方式、认证逻辑、测试流程、代码风格偏好，今天重开会话就全忘了，还得重新解释一遍（00:14-00:33）。
2. 记忆是基础设施问题，不是换更强模型能解决的：当 agent 真开始参与长期项目开发时，记忆、上下文、项目习惯都会变成基础设施；模型再强，如果每次都从空白状态开始，效率还是会被浪费掉（01:56-02:16）。
3. 不要把项目说明、需求、历史决策反复塞进 prompt：不仅费 token，还容易过期、冲突、遗漏；memory 的思路是让 agent 自己沉淀、检索、复用记忆（02:29-02:50）。
4. 项目真正价值不只是让 AI 记住东西，而是把 AI agent 从一次性聊天推向长期协作工具（02:54-03:00）。

### 关键机制
- 统一 memory server：不是某个 agent 自己记住你，而是本地一个统一 memory server，各种 agent 通过 MCP hooks 或 REST API 从中读取项目记忆（00:37-00:55）。
- 记录内容：一次会话中 agent 修改了哪些文件、跑了什么命令、遇到过什么坑、最后采用了什么方案；这些信息被压缩成可搜索的记忆（00:57-01:08）。
- 官方例子：第一轮做 JWT 登录，第二轮让 agent 做限流；正常情况下得重新告诉它认证中间件在哪里、为什么选某个库、测试覆盖哪些逻辑，有记忆后 agent 可以自己回忆起来（01:18-01:36）。
- 可视化与回放：本地 viewer 查看记忆如何建立，session replay 可回放之前的 agent 会话；可理解为给 AI 编程助手加了「工作日志 + 知识库 + 回放系统」（01:38-01:54）。
- 官方 benchmark：长期记忆检索任务上有不错召回表现，同时能减少大量重复上下文（02:18-02:27）。

### 可操作细节
- 介入方式：MCP hooks 或 REST API，可介入各种主流 agent 底层（00:37-00:45）。
- 记忆粒度：文件改动、命令执行、踩坑记录、方案决策四类事件（00:57-01:05）。
- 成本指标：减少重复上下文，避免大段项目说明反复进 prompt（02:18-02:42）。
