## 内容提炼
### 核心论点
1. 同一场会话在 Claude Code 里同时存在三个版本：交互历史（屏幕上可回滚的聊天记录）、接口视图（真正发给模型的那份消息）、逻辑链（磁盘上决定下一轮从哪条消息接着涨的主线）；三者可以各不相同——界面上还看得见的，接口视图里可能已删；接口视图消失的，磁盘上可能一个字没少（00:33）
2. 判断任何压缩机制只需三问：它改的是哪个版本？什么时候触发？改完之后原始信息还找不找得回？（01:01）
3. 提示缓存一致性主导整套设计：服务器按前缀逐字节匹配缓存，前缀改一个字后面全部失效重算；因此「宁可多花 token 也不改一个已发出的字」（01:26 / 01:48）
4. 磁盘会话记录是只追加文件，所有机制都不改旧行只往后追加；删除和压缩不是抹掉过去，而是追加一条「怎么看过去」的说明，恢复会话时重放全部记录（09:26 / 13:19）
5. resume 是一次运行时迁移而不只是文件读取：从副指针图找回活动链、重放投影记录、修复中断的不完整结构（工具调用-结果配对、角色交替合法、补继续执行消息）、恢复文件/技能/工作现场，只恢复聊天文字会导致「界面一样但工作现场变了」（10:41 / 11:07）

### 关键机制
- 投影链路八环节：截取（只保留最后压缩边界之后的逻辑）→ 工具结果外置 → 微压缩（清旧工具结果）→ 上下文折叠 → 全量压缩 → 阻断检查，全部只改发送给模型的那份（02:12-03:07）；「不动原件只改发出那一份」即投影（02:20）
- 冷/热缓存双路径：缓存已冷则直接把旧结果换成占位文字（前缀反正要重建）；缓存还热则本地三个版本一个不动，改用服务器端缓存编辑删旧结果（04:19-05:04）
- 全量压缩：把边界前整段历史总结成摘要，之后请求不再携带旧历史；摘要生成请求从主对话分叉一个子代理、刻意保持相同配置不设输出上限，就为命中已有前缀缓存（05:18-06:01）
- 协议完整性优先于 token 上限：切点若把工具调用和它的结果拆开、或把同一条消息的思考片段切散，接口直接拒绝；宁可多保留也不切断（06:54-07:13）
- 副指针图：会话文件逻辑上是带分支的图而非数组，每条消息记自己的上一条逻辑消息；全量压缩的新边界=刻意留空的副指针，回溯到它就停（10:02-10:38）
- 响应式压缩：其他机制在请求发出前主动做，它只在服务器真拒绝后启动；整条恢复链只允许尝试一次，失败直接暴露原始错误，防恢复逻辑自己把上下文越滚越大（08:21-08:57）
- 三条设计原则：缓存决定必须可重复预览（原样重现）；接口结构完整性优先于 token 上限；磁盘只追加逻辑历史靠投影重建（12:56-13:28）

### 可操作细节
- 工具结果外置：不做语义摘要，把过大结果整个写到磁盘，接口视图换成一小段预览+文件位置，模型需要细节再读；预览一旦发出每轮原样重现不再改动（03:14-03:48）
- 上下文折叠与自动全量压缩互斥（折叠一开自动压缩不再触发）（07:40）
- snip（删中间一段历史）：磁盘留一条边界记录被删节点的精确清单，恢复时按清单重放删除，可精确重放（07:49-08:15）
- 绘画记忆压缩（实验变体）：后台子代理随推进持续把目标/进展/关键结论写成结构化笔记，压缩时直接拿笔记顶上省一次摘要调用，但仍保留最近一段原文当尾部（06:26-06:53）
- 客户端 token 估算不可靠是响应式压缩存在的根因（08:33-08:41）
- resume 与 fork 之分：resume 接管原会话 id 续写主线；fork 全新 id 另开时间线，但旧会话「工具结果换成预览」的决定必须一并带进新链，否则前缀突变缓存失效（11:45-12:18）
