## 内容提炼
### 核心论点
1. 产业界已用脚投票选择文件系统式记忆（Anthropic 记忆工具直接把记忆暴露成文件目录、靠六个通用文件操作管理；Claude Code 把智能体笔记存在索引过的记忆文件夹里；上下文文件、技能文件都用仓库里的 markdown 交付），但学术界此前没做过系统研究；「只要把内容存在文件里智能体自己就能管好、存得越多越好用」的默认假设没经过验证——时间长了记忆会累积出重复、矛盾、过时，同一主题散在多个文件，做不好反而比没有记忆的效果还差（00:45-02:00）。
2. 论文架构拆三个角色、共用同一个存储：**管理 agent**（把新内容块整合进存储、保持组织结构）、**搜索 agent**（查询存储、返回带引用来源的答案或检索到的技能）、**可选执行 agent**（实际做任务，体验数据变内容块交给管理 agent，也用搜索到的技能完成任务）；角色间契约简单，完全对应已落地系统，同一个模型可以同时扮演三个角色（03:15-03:57）。
3. 核心实证发现：**没有一种组织结构在所有场景拿到最高正确率**，组织带来的明确收益是搜索成本（内容越多收益越明显）；整理是否划算看场景——强执行 agent 用逐字会话日志效果最好，弱执行 agent 反而用提炼过的指导内容更好；对话场景管理 agent 能力只影响组织风格不影响回答质量、搜索 agent 越强收益越直接，技能场景是阈值问题——管理 agent 一旦过能力门槛，存储内容质量比执行模型能力更重要（07:34-08:59）。
4. 可持续性：测试时间范围内存储越大反而越有用，积累的经验甚至能替代执行 agent 的能力；但有副作用——组织合规性（良好组织的五条原则）随内容变多逐渐下降、整理成本线性增长、逐字转储的存储变大后检索返回太多无关内容、不加强制保留规则时智能体整理会默默压缩丢细节（09:05-09:56）。
5. 两个行业默认假设「只对了一半」：智能体确实能让不断增长的存储保持有用和健康，但组织的效果是有条件的，且组织本身不一定能直接提升答案正确率——正确率提升还是要靠搜索 agent 的能力（10:28-11:14）。

### 关键机制
- 六个记忆变体梯度（对照设计）：baseline（无记忆库，测性能下限）→ 块检索（普通 RAG，对话切块+BM25）→ 逐字转储（每个会话一个文件、完全不做整理，零成本极限）→ 文件夹会话（只把逐字转储文件用大模型分到不同文件夹、不修改内容）→ 重组存储（跨会话拆分合并，分默认压缩版与保留全部事实规则的保留版）→ 完全智能体整理存储（从空库开始，管理 agent 边接收内容边组织）；把「分类整理」与「内容修改」的影响分离开（04:54-05:35）。
- 实验设计巧思：搜索 agent 用的工具是文件系统原生的只读工具（查看文件、正则搜索、读目录、读章节），**没有用向量/语义检索**——逼搜索 agent 必须自己导航存储的组织结构，才能测出不同组织方式的真实差异；加了语义检索结构的作用就会被搜索引擎掩盖（05:49-06:23）。
- 反直觉发现：管理 agent 会生成按主题分类的目录树，但**树的形状更多由模型能力决定而非内容规模**——内容变多时存储反而合并而不是拆成更多碎片，层级结构在文件夹/文件/文件内标题之间转移（06:57-07:33）。
- 工具集是杠杆：加一个工具只会改变 agent 的行为不会改变最终结果；换掉整个工具集会直接重塑存储形态，方向和收益由场景决定——长对话场景工具集让存储拆分，技能场景让存储合并（10:04-10:27）。

### 可操作细节
- 落地指导：场景最在意搜索成本（尤其记忆规模会不断变大）→ 做整理划算；执行 agent 能力弱 → 给他提炼过的记忆内容；强执行 agent → 直接用原始日志更好；模型能力投入优先级——对话场景先给搜索 agent，技能场景先保证管理 agent 过能力门槛；工具集按场景选（11:52-12:27）。
- 数据集：对话场景用 LoCoMo（长多轮对话问答）、PersonaMem（带用户画像的长对话流）、RealTalk（21 天真实人类聊天记录）；技能场景用 LFQA 类基准测试「技能能否迁移到新任务」（04:30-04:53）。
- 实验变量：管理 agent 用 Anthropic 记忆工具的六个通用文件操作（查看/创建/字符串替换/编辑插入/删除/重命名）+ 行及正则搜索；还做了不同模型能力（弱到强多个档位）与不同工具集（加 BM25、换 bash shell）的对比（06:23-06:47）。
- 开放问题：现有质量基准对记忆的形状不敏感（很难测出组织结构对答案质量的影响）；更长时间跨度的可持续性未验证；组织原则偏泛、如何按场景细化；存储健康度自动评估；文件系统记忆与多模态结合；多智能体共享记忆的权限管理与并发修改（12:28-13:31）。
