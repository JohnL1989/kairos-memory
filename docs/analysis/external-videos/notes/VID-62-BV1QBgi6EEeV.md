## 内容提炼
### 核心论点
1. 深度搜索失败的主因是「一边走一边忘」：归因分析显示 83%~93% 的失败轨迹中，模型中途明确计划过要查某些分支，最后没查完就给了答案——轨迹拉长到十几万 token 后，早期定下的计划被不断累积的工具调用和网页内容淹没（01:19-01:37）
2. 多次采样投票（多数投票/加权投票/best-of-n）有硬伤：各次尝试彼此独立、每条轨迹从零开始，既重复搜索已查过的东西，也无法把「哪条路已证明是死的」告诉下一次——经验没留下（01:38-02:08）
3. RE-TRAC 的解法是**递归轨迹压缩**：每轮探索结束前把整轮轨迹压缩成一份结构化状态交给下一轮，让多次尝试从「彼此独立的尝试」变成「渐进式学习」（02:13-03:03）
4. 效果显著且更省：BrowseComp 上 O3 等前沿模型准确率普遍提升 15~20 个百分点；token 用量与工具调用次数随轮次单调下降，达到同样甚至更好准确率只用投票类方法约一半资源（00:50-00:57 / 05:07-05:32）
5. 压缩状态不是金科玉律：早期实验发现模型过度依赖总结会卡在旧搜索路径里，对策是在下一轮输入中加明确指令「这份总结只是建议、可能有幻觉，你可以怀疑它推翻它；任务没解决就要主动扩大搜索空间」——消融实验显示加此提示后 O3 每轮准确率更高（03:23-03:48）

### 关键机制
- 结构化状态记三件事：①当前最可能的答案和关键推理结论（给后面当锚点）；②证据库和来源验证情况（哪些来源查过、哪些结论验证过，避免重复调用工具）；③不确定项和待探索方向（未验证的假设、被遗漏的分支、失败/放弃的方向）（02:26-02:41）
- 受控多样性：状态里同时保留多个未解决的候选方向，防止探索塌缩到一条路上（03:07-03:14）
- 两种用法：①免训练测试时扩展——直接套在 O4-mini/O3/GPT-5/DeepSeek-v3.2/GLM-4.7 上，与投票类方法对比（04:37-05:07）；②训练小模型——合成 3.3 万问答对（维基实体树根递归搜索构造多跳子问题+O3 模糊化），过滤出 10.4 万轨迹样本，SFT 训练出 RE-TRAC-4B 与 RE-TRAC-30B（05:38-06:08）
- 压缩质量决定上限：4B 模型把总结者换成更强的 GLM-4.7 后 BrowseComp 从 30.0% 涨到 38.5%，但 30B 换同样总结者反而微降（53.0%→52.4%）——说明小模型的压缩能力是瓶颈、30B 自己总结已足够好（07:32-07:58）

### 可操作细节
- 结构化状态的三项内容清单（02:26-02:41）
- 防过度依赖的提示词内容：「总结只是建议、可能有幻觉，可怀疑可推翻；任务未解决主动扩大搜索空间」（03:31-03:38）
- 消融数据：O3 八轮从 68.9% 提到 71.7%（03:48-03:50）；O4-mini 25.7%→46.8%、O3 54.9%→69.8%、GLM-4.7 37.7%→60.7%（04:50-05:05）
- 小模型训练结果：RE-TRAC-4B 五个基准全为同尺寸最佳（BrowseComp 30.0%、GAIA-A 70.4%、X-Bench 76.6%），超过所有 15B 以下基线；30B 达 53.0%，超过 358B GLM-4.7 的 52.0%（06:16-06:52）
- 边界：默认跑 8 轮；论文无延迟数据，串行 8 轮牺牲并行度，延迟敏感场景需自测（10:34-11:05）
