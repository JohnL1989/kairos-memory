## 内容提炼
### 核心论点
1. 记忆管理最核心的理由：防止对话到后面 AI 把前面关键内容忘记；其核心就做三件事——「存什么、存在哪里、怎么存」，外加「怎么检索和召回」（02:08-02:41）。
2. 不是所有对话内容都要一股脑存进去，而是让 AI 理解对话内容、抽取关键事实（如「张三喜欢喝咖啡」）再存——「存什么」的关键在事实抽取（02:47-03:15）。
3. 存哪里：主流是向量数据库存语义，为存事实间关系还会用图数据库（知识图谱三元组），方便后续推理（03:18-03:33）。
4. 怎么存的完整链路：理解上下文→抽取关键事实→基于向量相似度匹配查重（判断是新增还是对旧记忆增强更新）→调用接口存事实→把事实拆成三元组存进图库（03:38-04:38）。
5. 检索召回支持多路：语义检索（向量匹配）+ 关键字全文检索 + 实体增强的图检索（沿知识图谱连接线做多跳推理）；多路召回必然出现冲突，所以第二步要做召回内容的优先级排序（04:45-05:48）。
6. 结尾建议（作者借书友讨论提出）：不必引入向量库+图库这么复杂，可参考 Karpathy 的 LLM 知识库构建思路——本体建模+知识编译，抽象出上下文对话的核心知识原模型（存储量小），细粒度资料作为二级索引关联，分层记忆更好地管理长上下文（05:57-06:42）。

### 关键机制
- 记忆分型：单次对话记忆、整个会话记忆、用户记忆、更高层的组织记忆（02:00-02:08）。
- 记忆管理三问框架：存什么（事实抽取）→ 存在哪里（向量库+图库）→ 怎么存（查重后新增/更新，拆分三元组入库）（02:28-04:38）。
- 图库多跳检索：顺着知识图谱连接线一直检索到更深层相关内容（05:26-05:35）；多路召回冲突解决+优先级排序（05:35-05:48）。

### 可操作细节
- 相似度匹配决定「新增」还是「增强更新」：抽取出事实后先基于向量相似度检查原记忆是否已存过，是新增内容还是仅做增强更新（03:51-04:03）。
- 三元组化：事实存储后拆分为标准知识图谱三元组（实体-关系-实体，如「张三-喜欢-咖啡」）存入图数据库（04:25-04:38）。
