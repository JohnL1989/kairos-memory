## 内容提炼
### 核心论点
1. 四款主流方案（g-brain、graph-rag、graphify、llm-wiki）在做完全不同的事情，不是同一类东西；先想清楚你要的是哪一件事——让 agent 记住客户（对话记忆）、跨文档综合回答、让 AI 看懂代码仓库、还是让 AI 帮你整理更新笔记（00:08-00:44）。
2. g-brain（给在跑的 AI agent 装长期大脑）最关键的设计：把「持久世界知识」和「agent 临时工作状态」做了切分，不混在一起；代价是与 open-claw/HERMES 生态强绑定（01:09-01:22）。
3. llm-wiki（Karpathy 的 1.2 万字设计模式 gist，无仓库无产品无 API）把持久知识库从向量库切回 markdown 文件夹：每次扔新材料进来让 LLM 读完去更新已有的 wiki 页面，而不是每次提问在线查现答；整个知识库就是 git 管理的 markdown 文件夹（02:27-02:55）。
4. 大实话：这四款不是替代关系，理论上可以拼起来（graphify 做代码结构层 + g-brain 做 agent 长期记忆层 + graph-rag 做企业文档处理层），但目前公开的拼起来用案例还很少；star 数高不等于适合你（05:16-05:46）。

### 关键机制
- g-brain：记忆人、公司、会议、对话、待办这类世界知识，同时保留 agent 在跑什么任务、跑到哪一步的运维状态；持久知识与临时状态切分（01:03-01:14）。
- graph-rag（微软）：先用 LLM 把文档里的实体和关系抽出来建成大图，再用聚类算法把图分成主题块、每块写摘要；四款里唯一原生支持跨整批文档处理综合性问题的方案（01:24-01:43）。
- graphify：对 Carpy 那篇 gist 的直接实现（2026 年 4 月初创建），让 coding agent 直接走图谱看结构、减少在大仓库里来回 grab 文件；本地跑、一行命令装完（01:58-02:22）。
- 五维对比框架：谁在消费这套知识（agent 读 / 人读）/ 装起来难不难 / 要花多少钱 / 能记多少东西 / 换模型能不能用（03:02-04:15）。

### 可操作细节
- 成本数据：graph-rag 索引 500 页文档一次约 50-200 美金，同样语料 light-rag 约 0.5 美金（01:50-01:56）；graphify 官方提到的 71.5 倍省 token 是特定语料下的结果，换语料数字会变（02:20-02:24）。
- 选择清单：整理笔记/读论文/长期研究 → llm-wiki 两层文件夹先跑两周；每天用 coding agent 且仓库一大就找不到东西 → graphify 先挑中等仓库跑出图；公司内部知识库跨文档综合 → graph-rag 先拿 30-50 份文档做最小索引；搭长期跑的 agent 记客户 → g-brain（04:16-04:58）。
- 验证方法：给自己两周时间跑最小 demo，到点回头看四个数——搭建时间、索引成本、回答质量、自己改起来顺不顺（05:49-05:56）。
