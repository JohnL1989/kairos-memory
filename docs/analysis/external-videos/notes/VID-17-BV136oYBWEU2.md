## 内容提炼
### 核心论点
1. 朴素 History 数组记忆的三个痛点：无限叠加直到撞上模型上下文窗口上限（报错或被迫截断）、上下文膨胀导致 token 花费水涨船高、跨窗口重开即重置（Agent 对之前发生的事一无所知）（00:15-01:17）。
2. 从人类记忆三层次推导 Agent 记忆设计：工作记忆（当前焦点、容量小）= History 数组，纯粹流淌在内存中不需要本地写入；情景记忆（按时间浓缩成场景、被时间节点或情境触发回忆）= 按时间建立索引文件；核心记忆（长线目标、丧失则短视失忆）= 核心记忆文件常驻（01:53-04:40）。
3. 冷/温/热三级温度分层 + token 记忆：原始层（History.json 原封不动保存对话+API 调用量记录，冷记忆，每次调用模型后写入，不常驻上下文，仅用于审计回查）；中期层（以日期为索引的 md 文件记录当天摘要/心得/决策，温记忆，每轮压缩时触发写入）；长期层（`memory.md` 常驻上下文，热记忆，记录核心目标/当前任务/用户既定事实，每轮压缩中合并重写并限制膨胀）；叠加用户偏好文件（`user.md` 常驻，检测到偏好信号才写入，让 Agent 越用越顺手）（04:45-05:40）。
4. 压缩触发式写入循环：用户输入→写入 History 数组与 History.json→模型调用花费记入 tokens.json→模型回复写入→判断上下文是否超过阈值→未超继续，超过则触发压缩机制→压缩中同步阻断 Agent→压缩完成后才回复当轮 AI 回答→History 数组截断到当前时轮（07:16-08:08）。

### 关键机制
- 三层记忆文件的具体形态：History.json 永不覆盖、始终保留完整历史记录、不占上下文不花 token、仅用于审计和回查，双写（用户输入+模型输出都写入），保证 JSON 安全序列化（存储结构=时间戳+用户身份+具体内容）（05:58-06:30）；日期 md 文件以日历中具体一天为切片、压缩时触发写入、不占上下文、Agent 用工具检索（06:30-06:55）；`memory.md` 常驻系统提示词、采用复写策略、设置参数化字数膨胀上限（07:02-07:16）。
- 一次压缩同时完成三件事：把 History 数组维护的旧对话（排除当前最近 N 轮）转换为文本做一次 AI 调用，同时处理 `memory.md`、`user.md`、今日情景 md 三个文件的更新；为了低延迟和高吞吐合并调用，若追求更好效果可拆分为三次独立调用、各做一件事更专业（08:13-08:44）。
- 压缩提示词文件设计：older conversation（待压缩旧对话）+ 当前 `memory.md` + 情景文件（可置空——可用追加策略，每次压缩在原有记录上向后叠加，符合情景文件单纯记录事情的设计初衷）+ 三个输出文件（`memory.md``/user.md`/今日情景 md，每个内部包含不同要求）（08:52-09:19）。
- 六个可调关键参数：①触发压缩的上下文阈值；②保存当前对话注意力的数组保留轮数；③情景文件的划分颗粒度；④是否同步压缩；⑤Agent 访问记忆的工具；⑥```memory.md``` 的字数约束上限；通过实际过程中不断试错微调（09:27-09:47）。
- 代码模块：builder agent 示例、skill 目录（每个子目录一个技能）、Agent 主体模块化拆分（模型上下文压缩、context、loop、memory、runner、tools）、memory 目录（`history.json/tokens.json/memory.md``/日期 ``md/soul.md````/user.md````/压缩提示词/identity.md```），全部技能拼进系统提示词（09:47-12:42）。

### 可操作细节
- 实现自建记忆系统可照搬的最小文件集：history.json（原始对话，审计回查）+ tokens.json（花费记录）+ ```memory.md```（核心目标/任务/用户事实，常驻）+ 日期 md（情景摘要，追加式）+ ```user.md```（用户偏好，信号触发写入）（05:58-07:16，11:33-12:20）。
- 压缩参数起步值：保留最近 N 轮对话的注意力，其余压缩进 memory 文件；情景文件颗粒度建议以天为单位（09:27-09:47）。
- 压缩调用可合并（低延迟、高吞吐）也可拆分（效果更专业），按需求取舍（08:13-08:44）。
