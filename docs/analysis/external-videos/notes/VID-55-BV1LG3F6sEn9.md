## 内容提炼
### 核心论点
1. 长期陪伴型记忆的面试题核心「根本不是怎么存，而是怎么筛选和怎么调取」——把所有历史塞进上下文在 100 轮后必然 token 成本飙升且模型抓不住重点（00:12-00:30）
2. 三层分层存储：短期会话记忆（最近 N 轮完整对话原封不动直接喂模型，保当下连贯性）+ 结构化用户画像记忆（事实信息提取成标签存档案）+ 长期情景记忆（非结构化内容切片向量化语义召回）（00:33-01:46）
3. 事实类信息（姓名/偏好/禁忌/重要经历）「不能直接扔去向量数据库」，必须通过专门处理程序提取成结构化用户标签存专属档案，触发相关话题直接调取（01:00-01:21）
4. 记忆更新放后台异步线程：提取标签、存储向量都是耗时操作，不能让用户在前端等；同时**自动修正有冲突的旧信息**——「记忆是动态迭代的，而不是一成不变的死数据」（02:13-02:35）
5. 三大总结：分层存储（不要所有内容混存）/ 分类检索（事实查结构化库、非结构化内容语义召回，各有分工）/ 动态维护（更新与修正机制）（02:41-03:01）

### 关键机制
- 回答生成逻辑本质是 RAG：系统提示词 + 用户画像标签 + 检索到的历史记忆片段 + 近期短期对话，拼接成完整 prompt 再喂大模型（01:49-02:03）
- 短期记忆保证上下文连贯性：上一句说的事下一句能立刻对应上，不出现断片（00:43-00:52）
- 长期情景记忆属模糊召回：切片段转向量存向量库，聊到相关话题按语义相似度调取匹配度高的历史片段（01:25-01:46）
- 后台异步线程随对话推进默默梳理刚结束的对话，更新用户档案、补充记忆库、修正冲突旧信息（02:13-02:31）

### 可操作细节
- 三层各自的存储形态：短期=完整对话原样保留；画像=结构化标签/用户档案；情景=向量片段（00:37-01:46）
- 画像字段示例：姓名、偏好、禁忌、重要经历（01:11-01:15）
- 「聊到几百上千轮，只要触发相关话题直接调取档案，准确度很高基本不会出现偏差」（01:16-01:21）
- 架构记忆口诀：分层存储 → 分类检索 → 动态维护（02:41-03:01）
