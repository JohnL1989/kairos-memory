## 内容提炼
### 核心论点
1. 看 GitHub 项目的标准路径：About→代码结构→README→Issues（提前发现已知问题、节省配置时间）→环境复现→代码精读；Issues 是项目缺陷与可优化点的富矿（00:30-02:03，04:38-05:09）。
2. MemoryOS 代码骨架：memory_os.py 主类协调组件，short_term.py / mid_term.py / long_term.py 三层 + updater.py + retriever.py + prompt.py；核心参数：短期容量 7、中期热度阈值 5、检索 K=10、长期知识库容量 100、中期相似度阈值 0.6（35:49-37:05，38:00-38:56）。
3. 中期记忆是最复杂核心：段页式字典（sessions→pages→QA对+时间戳），LFU 最小堆维护热度（堆顶=最热），summary embedding（4096 维）做段级检索，先 topM 段再 topK 页两阶段（47:20-49:20，53:06-55:00）。
4. 系统设计缺陷：不支持定向删除记忆（删除只能全清），embedding 不支持配置 API URL（UP 主自行修改代码支持硅基流动 API）（05:36-07:26，25:44-26:07，40:43-40:51）。
5. 评测管线：LoCoMo 数据集（57 个 qa，约 2000 个问答对）→生成回答→F1/BLEU 计算；另有 30 问旅行规划 demo 用关键词命中率评估（31:19-33:45，28:07-30:57，63:26-66:42）。

### 关键机制
- 热度公式实现：α=β=γ=1（三因子等权），R 为指数时间衰减，半衰期设 74 小时（50:00-50:30）。
- 短期→中期：弹出最旧 QA 对→构造页面→与各段 summary 算相似度（语意余弦+关键词交并比）>0.6 合并进现有段，否则新建段→更新热度、重建堆（50:46-53:04）。
- 中期→长期：执行两个 prompt 任务（用户画像分析+知识提取）更新用户/助手画像，晋升后重置该段 L_interaction（41:59-42:47）。
- 检索：短期直接取队列全部 7 条；中期 topK 页（堆维护最高分）；长期 top10 语义向量；三层并行线程执行（工程优化）（57:46-58:32）。
- 对话链：页面记录前一页/后一页链接，构建对话链后再生成多轮摘要（56:27-57:15）。
- ChromaDB 工程版：向量检索 O(log n) 替代 JSON/FAISS 的 O(n)（28:48-30:00）。

### 可操作细节
- 复现环境：conda 创建 python3.10 + requirements.txt（faiss-gpu 安装失败需注释掉）+ tiktoken（11:06-12:17）。
- 评估 success rate = 输出中关键词命中数/关键词总数（30:13-30:57）。
- 记忆存储目录按 user_id/assistant_id 划分；短期/中期/长期记忆为 JSON 层级字典（16:43-20:41）。
- 部署集成：MCP 接口把记忆系统接到其他客户端；Docker 容器化部署（67:23-70:34）。
