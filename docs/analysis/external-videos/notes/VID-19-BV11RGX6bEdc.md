## 内容提炼
### 核心论点
1. 三个常见误解的纠正：记忆不全靠模型本身的上下文窗口，也不需要什么复杂的数据库配置，更不能干脆不管（那样 agent 每次对话都跟第一次见面一样）；OpenClaw 核心就三件事——`memory.md` 文件、daily notes 日常笔记、`dreams.md` 梦境日记（00:07-00:36）。
2. 三层记忆分工：`memory.md` 是长期记忆（持久的事实、偏好和决策，每次对话启动时自动加载）；daily notes 是工作记忆（memory 目录下按日期命名的笔记，保存运行中的上下文和观察，系统自动加载今天和昨天的）；`dreams.md` 是可选的背景整合（dreaming 系统的审核输出，回顾 agent 如何把短期记忆提升为长期记忆和新规则）（00:55-01:53）。
3. 「模型只记得写入磁盘的内容，没有隐藏状态，一切透明可追溯」——不是靠隐藏状态，而是靠写入磁盘的纯文本文件，透明可控还能查验，「就像你写日记一样」（01:03-01:53）。
4. 行动敏感记忆：有些记忆不只是记录事实，还要告诉 agent 什么时候该做什么——需要批准才能执行的操作、当前对话里不要做的事、另一个对话/线程正在处理的交接场景、特定时间之前不要执行的过期条件、等待某个条件满足才能行动的安全时机；关键要写清楚「改变什么行为、什么时候适用、什么时候过期」（03:05-03:37）。
5. 自动维护三件套：dreaming（可选背景记忆整合：收集短期信号评分候选，把合格的提升到长期记忆，目标是让 `memory.md` 保持高信噪比、不杂乱，默认关闭）+ compaction 前的静默步骤（回顾当前对话里的重要上下文自动保存到记忆文件，防止重要信息在压缩中丢失，开箱即用）+ memory replay backfill（重放旧的 daily notes，检查哪些内容值得长久保留）（04:39-05:09）。

### 关键机制
- `memory.md` 的内容边界：适合放用户偏好（喜欢用 TypeScript、默认模型）、持久决策（API 迁移方案）、重要约定、从日常笔记里提炼的精华总结；原始对话记录和日常日志不适合放这里；`memory.md` 太大超过引导预算时系统会自动截断，可用 /context list 查看原始大小和注入大小，把详细内容移回 daily notes（01:58-02:30）。
- daily notes 的维护：文件名 `memory/YYYYMMDD.md``（支持带标识的变体如「2026-2025 对话记录.md」）；agent 会逐步从 daily notes 里提炼有用信息到 ``memory.md``，同时移除过时的条目保持记忆干净；daily notes 像工作台笔记，``memory.md` 像整理好的知识库，定期整理才能保持高效（02:31-02:58）。
- 记忆工具：memory search（语义搜索+关键词匹配，措辞不同也能找到相关笔记）、memory get（读取特定记忆文件或行范围，精确提取）；CLI 有 memory status（检查索引状态）、memory search（关键词搜索）、memory reindex force（重建索引）（03:38-04:06）。
- 四种后端引擎：builtin（基于 SQLite 默认引擎，开箱即用，支持关键词搜索、向量相似度、混合搜索，适合大多数用户）；QMD（本地优先，带重排序和查询扩展，还能索引工作区外的目录）；hunter AI（原生跨对话记忆，支持用户建模和多 agent 感知）；LDB（基于 LSDB，支持 OpenAI 兼容嵌入和本地嵌入）；另可安装 memory wiki 插件把持久记忆编译成带溯源的知识库（04:07-04:37）。

### 可操作细节
- 想让 agent 记住什么直接说「记住我喜欢用 TypeScript」就行，agent 会自动写入合适的文件（05:10-05:17）。
- 要定期整理 ```memory.md```，不要存太多细节，详细内容放 daily notes；用 /context list 查看预算使用情况（05:20-05:31）。
- 行动边界要写清楚：当记忆涉及「什么时候能做什么事」时，务必写明适用条件、过期时间和要避免什么（05:27-05:32）。
- 后端选择：builtin 默认够用，其余引擎覆盖本地优先/跨对话/自定义嵌入等不同场景（04:07-04:37）。
