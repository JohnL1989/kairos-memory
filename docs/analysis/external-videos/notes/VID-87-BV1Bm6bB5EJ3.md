## 内容提炼
### 核心论点
1. 推理服务本质：大模型就是个超大文件（训练时学到的知识参数），加载到内存对外暴露 HTTP 接口；无状态、多实例负载均衡，第一次请求打到机器 A、第二次打到机器 B，两个不同进程（00:22-01:07）。
2. Memory 的本质是上下文管理机制：大模型本身什么都不记得，每次请求把之前的聊天记录重新拼进对话；分短期记忆（当前会话最近几轮完整保存）与长期记忆（很久之前的对话提取关键信息压缩成摘要），每次请求拼接，大模型"看起来像有记忆"（01:30-01:49）。
3. RAG：模型训练数据是历史公开数据、训练完知识就固定了，配外部知识库（新闻/内部文档，向量数据库存储）解决；用户提问先从库里匹配相关知识再一起喂给模型（01:51-02:28）。
4. MCP：在对话里约定结构化消息格式（JSON），模型想用工具时输出特定格式，外部程序解析执行并把结果回传——这套协议规范就是 Model Context Protocol；分 MCP Host（Cursor/Claude Code）、MCP Client、MCP Server（GitHub MCP 插件例子）（02:55-04:05）。
5. Skills：有了工具（MCP）模型不知道按什么顺序组合用，需要一份结构化操作指南（遇到什么场景用什么工具、先做什么后做什么、注意事项）；排查线上事故 skill 例子：先看监控判断影响范围→查日志配置定位模块→必要时回滚（04:07-05:02）。
6. AI agent = 大模型（思考规划）+ Memory（记历史）+ RAG（外部知识）+ MCP（手/工具）+ Skills（操作经验）共同构成的自主行动系统；Clawdbot 本质就是本地电脑操作的 agent，无技术突破，与 Manus 同类（远端虚拟机隔离 vs 本地部署）；"安全是用户该考虑的问题"（05:03-06:11）。

### 关键机制
- 概念类比：大模型=大脑，MCP 协议=给它装上手，MCP 插件=手上的工具，Skills=操作经验（规定场景、顺序、组合）（04:55-05:02）。
- 记忆分层：短期记忆完整保存 vs 长期记忆摘要压缩，按需拼接（01:35-01:47）。

### 可操作细节
- 向量数据库选型举例：Milvus（数据量大）、PostgreSQL + pgvector（数据量不大）（02:49-02:53）。
- MCP 分层：MCP Host 解析 JSON 操作工具；MCP 插件拆本地 Client（收调用请求）+ 远端 Server（真正执行 API 操作）（03:43-04:05）。
