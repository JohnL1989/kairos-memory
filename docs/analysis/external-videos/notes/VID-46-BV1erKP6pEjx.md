## 内容提炼
### 核心论点
1. 大模型没有真正意义上的记忆：每次回答只是基于当前 prompt 推理，「所谓的记住了什么，都是开发者把历史信息重新组织好之后又喂给了模型」——agent 做得好不好很大程度取决于记忆管理系统设计（00:21-00:51）
2. 记忆应该存事实而不是存对话：全量历史回灌会 token 爆炸、旧信息干扰、成本上升，且会在某个时刻突然超上下文爆错；人类类比——记不住完整对话但记得「这个人喜欢吃川菜、正在装修房子」，「人类记住的是事实，不是对话记录」（02:37-04:52）
3. 记忆按生命周期分三层：短期（当前会话，内存/Redis，低延迟读写，按时间顺序取最近 N 轮）/ 中期（近期项目+最近几天摘要，按话题分组，TTL 7-30 天，超期先归档或压缩成更短摘要而非直接删除）/ 长期（稳定事实用户画像，写入门槛最高，每条保留来源便于回溯）（07:15-09:47）
4. 引入 Topic 维度打破时间线性：多主题对话按时间顺序保存会让模型在装修话题里引用宠物内容；每个 topic 维护自己的摘要/关键词/向量/历史，再聊装修只恢复装修组历史（09:49-11:27）
5. Topic 之间不能完全隔离：需要 Global Memory（常驻用户画像摘要，每次构建 prompt 直接拼进去不检索）和 Constraint Memory（约束表：content/confidence/importance/applies_to/updated_at 五字段）打通跨话题背景共享——「topic 划分得越干净，隔离带来的副作用反而越明显」（13:17-15:28）

### 关键机制
- 整体闭环流程：用户消息→判断长度（超长先进切分摘要）→话题路由（topic routing）→检索相关记忆（话题历史摘要+跨话题全局背景+约束条件）→contextBuilder 拼装 prompt→模型回答→从这一轮再提取新偏好/约束/事实写回记忆库、刷新话题摘要——「用户的每一次输入，既是这一轮的问题，也是下一轮记忆的原材料」（01:14-02:32）
- 沉淀门槛与置信度：单次表达 vs 稳定偏好没有清晰界限——同一偏好最近三次相关对话都被提到、或用「一直/平时/通常」这类持续性词才从候选提升为正式记忆；带时间限定/情绪色彩的表达（今天/突然/心情不好/想吃）即使记录也打低置信度+短 expires_at 自然过期；用户明确说的 vs 模型推测的置信度不同（用户说「我家有猫」高置信 vs 从猫抓板/猫粮推测低置信），contextBuilder 打分时体现差异（05:58-07:14）
- 长期记忆写入门槛与来源保留：写错纠正成本高（用户不会主动说「我并没有说过我是程序员」，只能靠后续矛盾信息慢慢修正）；每条长期记忆保留来源——哪轮对话、哪句话触发的提取，方便回溯（09:04-09:30）
- 话题路由两阶段：先 embedding 当前句子→与已有 topic 摘要相似度检索找出候选→候选有明显更接近的交模型做最终判断（语义相似不代表同一件事：装修预算和旅游预算向量距离可能接近但是两个话题）；所有候选相似度都很低→新建 topic 不勉强塞旧话题；threshold 参数：设太低新话题难建立（历史摘要被无关内容污染）、设太高同一话题被反复拆成多个新 topic（检索找不全历史）；先用真实对话离线评估观察误合并/误拆分比例，再结合线上反馈调整（11:29-13:14）
- Global Memory：保存影响很多话题的背景（职业/家庭/预算/城市/语言偏好/健康状况/宠物/老人小孩）；与长期记忆的区别：长期记忆按 topic 或需求检索具体事实，global memory 像每次对话默认加载的一小段用户画像摘要（类似 system prompt 一部分，不需要相似度检索）；实践中维护成结构化简短文本（「用户是一名后端工程师，居住在上海，家中有一只猫，预算相对宽裕」）每次构建 prompt 直接拼进去——省一次检索开销+保证不同 topic 看到的背景一致；不能无限增长需筛选压缩（14:01-15:27）
- Constraint Memory：单独维护约束表，每条记录五字段——content（内容）/ confidence（用户明确表达 vs 模型推测）/ importance（重要程度决定打分权重）/ applies_to（影响哪些 topic：装修/家具/清洁）/ updated_at（判断是否过期）；进装修 topic 按 applies_to 查约束自动带进上下文（模型自然推荐耐抓地板而非普通木地板）；applies_to 可人工预设也可让模型提取约束时顺带给出（「从我家有猫提取约束时在 prompt 里要求模型输出可能影响的话题列表」）；上线初期保留人工审核或允许用户查看修正；约束更新比普通偏好更保守（倾向覆盖而非简单追加——约束排他性强，预算 20 万被误判后推荐容易超出用户承受范围）（15:28-17:35）
- Topic 关联图：显示记录 topic 之间的关联形成图（不是单向链条）——装修连着家具/预算/收纳、宠物连着家具/清洁/旅行；关联可人工预设（装修-家具、宠物-清洁常识性关联）也可运行积累（某用户装修话题和旅游话题反复出现相似检索命中→提高这两个 topic 的边权重）；检索时除当前 topic 历史外按边权重取 1-2 个关联最紧密的 topic 各自召回少量相关内容纳入候选——不拉全部历史否则回到信息太多挤爆预算（17:42-19:14）

### 可操作细节
- 中期记忆 TTL 示例：7 天/30 天，或随项目结束失效（08:14-08:20）
- 约束表五字段：content/confidence/importance/applies_to/updated_at（15:49-16:24）
- 话题路由两阶段：向量召回缩小候选 + LLM 语义确认；threshold 需离线评估+线上调优（12:14-13:02）
- 关联 topic 召回：按边权重取 1-2 个关联最紧密 topic、各自少量内容（18:55-19:06）
- 沉淀门槛：同一偏好最近 3 次相关对话被提到，或出现持续性词（06:05-06:24）
