## 内容提炼
### 核心论点
1. 一个入门项目用同一套抽象基类实现九种 Agent Memory 策略（顺序/滑动窗口/摘要/检索增强/记忆增强/层次化/图记忆/压缩/操作系统式），每种给出难度、优点、劣势与流程图，是记忆实现方式的完整谱系（00:30-03:35）。
2. 记忆系统可插件化：BaseMemoryStrategy 抽象基类（add_message 增加记忆/get_context 获取上下文/clear 清空）+ 通用 Agent 类（chat 五步：检索上下文→拼 prompt→生成→写回记忆→输出），九种策略均插拔式接入（11:48-15:03）。
3. 检索增强（策略4）是 token 高效的关键形态：文本→embedding 向量（4096 维）→FAISS 向量库→余弦相似度 topK 召回，但可能错过语义检索不到的关联（24:45-28:31）。
4. 操作系统式记忆（策略9）：活跃内存(RAM)+外存双级存储，查询未命中触发 page fault 从外存换入，用 counter 记录使用频次做 LRU 淘汰（37:58-41:44）。
5. 无免费午餐（no free lunch）：没有一种策略在所有场景最优，需按 token 效率与信息保真度权衡选型（41:52-42:28）。

### 关键机制
- 摘要记忆（策略3）：running summary + buffer（临时缓冲区）+ summary threshold=4；缓冲区超过阈值才合并生成新摘要，否则直接用缓冲区内容（22:27-24:38）。
- 记忆增强（策略5）vs 层次化记忆（策略6）：二者都是短期（滑动窗口）+长期；区别在于策略5 长期记忆是"关键事实列表"（大模型事实提取 prompt），策略6 长期记忆走向量检索——本质是把 RAG 方法装进层次化记忆（31:51-33:50）。
- 图记忆（策略7）：大模型从对话中提取三元组（主体-关系-客体，正则表达式解析）→networkx 建图存储→检索时取节点的入边/出边关系作为上下文（33:54-36:45）。
- 操作系统式记忆（策略9）：RAM 容量满后按 LRU（最近最少使用）把最老记忆丢到外存；查询时先查 RAM，不相关则把外存中最相关的记忆换入（39:55-41:27）。

### 可操作细节
- API 配置：硅基流动（SiliconFlow）base_url + api_key；生成模型选 DeepSeek V3.2，embedding 模型选千问 3-embedding-8B（4096 维，作者原代码维度不一致需改）（03:38-09:20，25:09-25:36）。
- 滑动窗口 size=2 时第四轮提问会忘记第一轮信息（演示失败案例）；size=4 才记住（21:19-21:44）。
- 摘要阈值 4：缓冲区超过 4 条才触发合并（23:00-23:12）。
- 用 tokenizer（cl100k_base）统计 prompt/输出 token 以估算 API 成本与上下文窗口长度（10:04-10:32）。
