## 内容提炼
### 核心论点
1. TencentDB AgentMemory 的目标不是追求存下所有东西，而是解决三个问题：「什么值得留下」「谁可以使用」「下一次怎样少拿，但拿对」（00:11-00:16）。
2. v2.0 升级定位：从「四层记忆插件」进化为「团队记忆中枢」，把散乱的对话上下文重构为四大标准化、可复用的资产——ChatMemory（对话记忆）、Skill（技能）、Wiki 知识库、CodeGraph（代码图谱）（00:21-00:30）。
3. 冷启动独当（经验交接）：上一个 Agent 能成的任务，记忆原封不动移交给下一个 Agent，让经验在跨 Agent、跨流程的流水线中无缝交接——这是本项目区别于普通记忆插件的最大亮点（01:29-01:45）。
4. 「经验不是聊天记录，是可复利的资产」（04:29-04:32）。

### 关键机制
- Skill 资产化借鉴 Hermes Agent 经验沉淀机制：Agent 做完复杂工作后，从对话和工具调用中提炼可复用的 Skill；支持私有沉淀与团队共享，避免重复踩坑（00:52-01:07）。
- Wiki 知识库借鉴 LMWiki 理念：把产品运维手册和设计文档自动转化为结构化知识库与关联图谱；通过增量解析文档保证长文内容的高效检索，让新 Agent 随时继承团队积累的领域知识（01:08-01:28）。
- CodeGraph：实现对代码库的预索引（涵盖符号、文件、调用关系与影响路径），Coding Agent 在修改关键函数前可提前评估上游与下游影响，防止改代码引发连锁 Bug（01:46-02:02）。
- 评测数据：在权威学术评测中开启记忆后理解准确率从 48% 提升至 76%，相对提升约 59%（02:03-02:14）；UP 主实测将 Hermes 中近一个月使用的 1301 条 L0 对话、84 条 L1 原子记忆与 13 个场景块全量无损迁移，验证底层数据结构平滑兼容（02:22-02:40）。
- Docker 三件套部署：内核 Memory Core + 控制面板 Memory Hub + 代理接入层 Proxy，保证底层引擎高并发，通过透明代理无缝适配 Claude Code 和 Hermes 等主流 Agent（03:05-03:22）。
- 四级可见性（Private / Team / Restricted / Agent 运向装配），核心原则「共享经验不共享隐私」：Private 级别仅 Owner 可读写，即使 Team Admin 也无法越权（03:23-03:41）。
- Agent Loadout 机制：给不同角色（如 Skill Builder、Reviewer）配装不同的「记忆背包」，按需装配（03:42-03:52）。

### 可操作细节
- 记忆系统设计先回答三问：什么值得留下、谁可以使用、下次怎样少拿但拿对（00:11-00:16）。
- 迁移前用数据迁移工具验证底层数据结构兼容性（实测 1301 L0 + 84 L1 + 13 场景块无损）（02:22-02:40）。
- 接入顺序建议：先接入 LLM Wiki 和 CodeGraph，按需再接入其他功能（03:53-04:10）。
- 落地形态：一个 Agent 接入 12 个 MCP 工具（8 个 CodeGraph + 4 个 Wiki 查询工具）（04:10-04:19）。
- 注意：项目对 Windows 支持一般（03:53-04:00）。
