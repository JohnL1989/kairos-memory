## 内容提炼
### 核心论点
1. 记忆分短期/中期/长期三层，模拟操作系统「寄存器→内存→磁盘」的存储层次：短期=最近 N 轮对话，中期=按规则抽取的阶段性记忆，长期=再提炼的用户画像/用户知识/助手知识（04:11）
2. 层间流动由「热度值」自动调度：短期满则弹出最远轮次转中期，中期热度超阈值落盘长期，容量满删热度最低者（05:07 / 06:34 / 07:01）
3. 召回按需：短期整段放入 prompt、中期 top-k 检索最相关片段、长期中用户画像常驻、知识类检索（06:54 / 07:31）
4. 批评平铺式抽取框架（如 Mem0）：记忆碎片化（几千条琐碎事实）、更新过度依赖 embedding 相似检索形成「孤岛记忆」永远不被更新，主张归纳成情景记忆块 + 离线全局回顾（00:28 / 43:13）
5. 热度值公式三因子：检索命中次数、session 内配置数量、上次检索时间，加权计算（25:01）

### 关键机制
- 热度值公式：αβγ 三系数加权（中期检索命中次数、session 内配置数、上次检索时间），配置越多说明 session 越重要；初始值为 1（25:01-26:35）
- 短期→中期六步：弹出短期记忆→整理成「配置」（page，最小记忆单元，含 id/用户输入/回复/时间/前后配置指针）→连续性判断（LLM prompt）→元信息抽取（参考上一配置的元信息）→多主题摘要（最多两个主题+关键词）→写入 session（18:21-23:45）
- session 聚类：中期记忆按 embedding 相似把相似配置归并到同一个 session 统一管理（09:13 / 27:35）
- 中期→长期：中期用大顶堆维护（堆顶=热度最高），热度超阈值后并行执行用户画像提取与知识提取，完成后对配置「降温」清零部分参数防止下次仍弹堆顶（28:59-34:54）
- 检索流：query 并行检索中期记忆/用户知识/助手知识，短期与用户画像固定读取，按固定模板拼接成 prompt；回复后固定调用 add_memory 写回（35:47-40:37）
- 离线全局回顾（借鉴 Hammers 的 skill 自优化思想）：定时把全部记忆放进一个 prompt 宏观审视，识别可合并/无用的记忆后整体更新（42:50）

### 可操作细节
- 短期容量可配置（演示设为 3 轮）（13:27）
- 中期容量示例为 2000 条（07:22）
- 热度阈值可调（演示调成 1 以触发落盘）（29:41）
- 连续性判断、元信息抽取、多主题摘要、画像/知识提取均为 prompt 驱动，可针对业务自定义（20:10 / 21:15 / 23:00 / 30:06）
- 用户画像维度 prompt 写得过细会限制模型发挥、强行提取不必要内容（31:25）
- UP 主指出缺陷：把全量对话历史拼接进 prompt 的方式无法利用前缀缓存，推理变慢（39:55）
