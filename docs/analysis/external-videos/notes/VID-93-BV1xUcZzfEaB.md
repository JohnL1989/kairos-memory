## 内容提炼
### 核心论点
1. 使用 OpenClaw 类产品三个问题：上下文爆炸（agent 执行任务反复出错，所有错误与运行日志都存进上下文，怎么去除）；跨对话失忆（第二天新开对话忘了昨天的失败经验，不加载要重复来一遍、加载则一个文件就消耗很多 token）；技能孤岛（一个 Skill 只是提示词里孤零零的知识点，在几万几十万长度的上下文里模型不会记住它）（00:00-01:19）。
2. 统一假设：记忆、Skills、Agents 的底层架构其实都是"上下文工程"（01:27-01:35）。
3. GraphMemory 解法：把执行过程中的采坑经验与成功经验提取为知识图谱，丢弃所有噪声——实测可压缩 70%，是主动压缩而非原版暴力压缩，实现快乐对话的可延续与自我进化（01:52-02:50）。
4. 图谱本体设计：实体三类（任务/使用的 skills/事件如报错），关系六类（任务使用了 skill、哪些问题用哪个 skill 解决、依赖、新知识、修正、旧知识、互补方案）（05:11-05:45）。
5. 图算法：基于 GraphRAG 的检索、个性化 PageRank、社区计算、语义相似度去重（05:49-06:00）。
6. 实验：7 轮问答（打招呼/安装/3-5 轮反复失败/授权/查询视频），原版 token 从 2 万涨到 5 万多且无法先处理、只能等阈值触发系统压缩（会丢很多）；图谱版主动提取后直接压到 1 万 6（06:50-08:06）。
7. 跨对话验证：新开对话窗口让 agent"使用技能回想一下今天发生的任务"，能从知识图谱拉取记忆列出已完成任务（需配置默认从知识图谱拉取记忆）（07:57-08:06，07:29-07:57）。
8. 动态知识体系：图谱持续累积形成自己的知识体系，可自己维护、增删改查（06:40-06:49）。

### 关键机制
- 实体-关系设计：任务（布置的任务）/ skills（使用了哪个 skill）/ 事件（报错）三类实体；关系边：任务使用了、问题解决、依赖、新知识、修正、旧知识、互补方案（05:11-05:45）。
- 主动提取时机：任务执行完成后提取（成功经验+采坑经验），噪声丢弃（02:20-02:40）。
- 检索：向量+个性化配置直取三元组（简单问题）/ 社区+时序过滤综合（复杂概念问题）（对应 VID-92 的双层召回，本集以实验形式呈现）。

### 可操作细节
- 安装：终端执行一条命令安装插件到 OpenClaw；插件列表确认；配置 JS 文件把上下文工程改为 graphmemory 插件，配置模型与嵌入模型（08:10-09:30）。
- 全文搜索降级：不使用嵌入时可用 FS5 全文搜索（08:39-08:43）。
- 实验数据：原版 7 轮 token 2 万→5 万+；图谱版压到 1 万 6；压缩 70%（02:42-02:50，06:50-08:06）。

## 存疑与未验证
- 「压缩 70%」「2 万→5 万+→1 万 6」为 UP 主单次实验数据（minimax 模型、特定任务），无可复现的评测协议（未验证）。
- 图算法（GraphRAG 检索、个性化 PageRank、社区计算）的实现与效果无独立评测，属自述（未验证）。
- 「模型反复失败叠加上下文」的现象描述依赖具体模型（minimax），换模型后结论可能变化（未验证）。
- 安装/配置步骤（JS 文件修改、FS5 全文搜索）随版本变化可能失效（未验证）。
