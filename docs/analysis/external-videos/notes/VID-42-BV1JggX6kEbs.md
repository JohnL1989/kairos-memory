## 内容提炼
### 核心论点
1. 大多数个人记忆系统的坑：笔记越记越乱检索靠翻；AI 给一堆总结准不准没空核，堆着堆着成垃圾堆；牛人系统（awesome-skills 的 memory palace：vault 硬拆五层 + 710 行蒸馏引擎 + 六维加权打分）强但一个人用光维护就累吐——把工具用成了负担（00:26-00:56）。
2. 自己这套的核心一句话：「最终判断权在你手里」——中间不靠机器替你筛选（01:02-01:06）。
3. 两个多数系统没有的设计：一是「纠错不删」——每条带 confidence 置信度，错了不抹掉而是标 invalidated 冷归档，因为 3 年前的判断可能只是前提变了，留着才能复盘；二是「类型化关联」——related / conflicts_with / supersedes / enables / causes，不是扁平相关而是带方向的因果网，你寄一条新东西系统会告诉你它推翻了哪条旧的（02:23-02:52）。
4. 对比 710 行引擎（全自动、能任意 agent 复刻），自己的选择是「轻、贴手、零维护」，且判断权从来没离开过人——对一个人用，这比加机器筛选更诚实：不延迟、不误删、不污染（03:31-03:49）。

### 关键机制
- 双线架构：一条线是记忆引擎，一条线是所有 agent 通用的行为规则（01:07-01:11）。
- 记忆引擎四步走（01:15-02:11）：
  1. raw_inbox：原始碎片先丢进 inbox，注意是原话、照存、永远不删——这是防污染的第一道闸，模型幻觉进不来，因为你随时能对照原话（01:16-01:30）。
  2. ingest：净化去重合并碎片落到 entries——「L0 真相层」；关键设计：经验不等于知识，带体温的经验可验证、可结构化的知识，两条轨不混（01:31-01:47）。
  3. build：生成 index.json——「L1 轻量索引」；库涨到几千条时单次对话只回摘要，token 封顶、不爆上下文（01:51-01:59）。
  4. recall（加权召回）→ evolve（演化）→ consolidate（凝成 entities）——「L2 心智模型」，让碎片自己长出连接、长出结构，知识不停增长变成经验，让 AI 能不停进步并纠错（02:00-02:17）。
- 行为规则线：不管用哪个 agent 上来，都知道你的爱好、你的禁止项；00rules 管「AI 和工具怎么对我动」（例如操作默认放 D 盘、视觉统一走极简风格），与 schema 分工明确——一个管数据怎么存，一个管行为怎么动，互不越界（03:07-03:28）。
- 实现形态：纯 Python 标准库、零依赖、索引可重算、`schema.md` 就是数据契约，谁都能看懂都能改（02:56-03:01）。

### 可操作细节
- 四步管道命名：raw_inbox → ingest → build（index.json）→ recall/evolve/consolidate（entities）（01:16-02:11）。
- 纠错标记：每条带 confidence，错误时标 invalidated 冷归档，不删除（02:26-02:39）。
- 类型化关联边集合：related、conflicts_with、supersedes、enables、causes（02:40-02:52）。
- 分级索引：L0 真相层（entries）→ L1 轻量索引（index.json）→ L2 心智模型（entities）（01:36-02:11）。
- 容量策略：几千条规模下单次对话只回摘要、token 封顶（01:54-01:59）。
