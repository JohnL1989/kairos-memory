## 内容提炼
### 核心论点
1. 长期记忆最现实的矛盾：长对话信息最全但最占上下文，极短摘要最省空间但细节和来源容易一起丢掉——上下文膨胀（context inflation）问题：Agent 交互越久历史越多，直接全塞回去不现实（00:32-00:48）。
2. 压缩不是越狠越好：摘要如果把来源指针也压没了，一旦写错就很难修；一个好的记忆单元应该能回到 ledger（账本）——因为 views 是近似的、压缩也会出错，系统只有能回到账本才有排账空间（01:22-01:36）。
3. 时间比压缩更麻烦：LLM 天生对时间不敏感，尤其隐含时间（「拜登是美国总统」2024 年没问题、2026 年就不对了）；语义检索只知道相关、不知道哪条当前有效；这不是模型多想一下能稳定解决的，这是架构问题（01:36-01:59）。
4. 时间会改变 ledger/views/policy 三层的语义：ledger 要回答两种时间——transaction time（系统什么时候写入或更正）与 valid time（事实在世界上什么时候为真）；views 检索要在查询时间语境下成立（time slice），没有时间切片旧事实就会被当当前事实召回；policy 也要显式选择范围——current 还是 historical（02:10-03:17）。
5. 分层记忆：同一段历史很难只用一种存储形态服务所有任务——图记忆（保存实体关系）、经验记忆（抽象处理模式）、片段记忆（保留原文，用于核对和溯源）；长期记忆不是越存越多也不是越压越短，要在压缩、溯源和时间之间做平衡（03:42-04:20）。

### 关键机制
- 记忆单元递规固化（转写「地規固化」，即递归固化）：不直接存原始文本，存压缩后的记忆单元，按单元之间的「亲和力」（是不是在讲同一类事情、能不能合并成更高层抽象、能不能减少重复）在后台做递归固化——相近记忆合并，底层事实变中层概括、中层概括变高层模式；像整理照片：底层留底片、上层按旅行生成相册、再往上年度回顾（00:48-01:22）。
- 冲突证据不要被系统私自裁掉：旧地址和新地址同时存在时，Memory OS 应该把证据结构交给 System 1，让推理层做判断（02:52-03:00）。
- 时间切片的价值：客户去年属于 A 项目、今年迁到 B 项目——问「现在谁负责」系统应看 current，问「去年那次故障是谁处理的」必须切到 historical，否则历史复盘会被当前状态污染（03:19-03:42）。
- 时序知识图谱方向（ZAP、GraphTT 类）：给图谱里的边加时间标注，用有效时间窗口区分「曾经为真」和「当前为真」（01:59-02:10）。
- 本集定位：Declarative Memory（陈述性记忆）——回答「是什么」和「发生过什么」（04:26-04:31）。

### 可操作细节
- 双时态区分：transaction time（写入/更正时间）与 valid time（事实有效时间）可以不同——今天纠正上周末的事实，写入时间是今天、有效时间可能是上周（02:20-02:32）。
- time slice 检索：检索不能只「相关即可」，要在某个查询时间语境下成立（02:38-02:42）。
- 分层存储对应任务：关系推理→图记忆；经验迁移→经验记忆；证据核对→片段记忆（03:42-04:10）。

- 「simpleman」（音译）——讨论 context inflation 的系统/方法，无法对应到已知系统（未验证）。
- 「ZAP」「GraphTT」（音译）——时序知识图谱/边时间标注方向的具体系统，无法核实（未验证）。
- 转写为繁体且错字较多（「語意相思度」「遞規固化」「Rolleder」等），按上下文校正（未验证）。
- 本集为系列第四集，Declarative Memory 为认知科学术语的工程借用，与 Kairos 记忆类型学（认知基础附录 D）的对应关系需另行核对（未验证）。
