## 内容提炼
### 核心论点
1. 基准问题：云端代理每次只创建一个相互隔离的会话，代理不记得过去、也不把信息传递到未来会话（02:05）
2. 记忆存储（Memory Store）= 可挂载到会话的持久化文件系统，模型具备读写该存储的能力（01:03 / 06:21）
3. 梦境（Dreams）= 后台运行的异步批量流程：分析会话记录与输入记忆库，事实核查、补充细节（日期/标识符）、去重整理，输出优化后的新记忆库（01:18 / 14:02）
4. 梦境是无损流程：完全不会修改输入的原始记忆库，克隆到「输出记忆存储」后在新库上写入（18:36）
5. 三层可组合：会话（独立运行的短暂实例）+ 记忆库（跨会话连接信息）+ 梦境（随时间为记忆库组织、优化、防失控）（25:13）

### 关键机制
- 记忆存储以文件系统形态挂载到会话容器，代理可用 bash 探索、grep 关键词搜索、读文件——「文件系统是强大的模型接口」（06:29-06:48）
- 访问控制：记忆库挂载时有访问字段，默认读写，可改为只读（只读则代理只能读取不能更新）（08:59-09:12）
- 提示词参数可引导代理读写特定信息（如投资代理聚焦记住的具体内容）（08:41-08:57）
- 记忆文件版本化：每次修改文件都创建新版本，提供版本相关端点（12:04-12:16）
- 梦境框架是多代理架构：协调器负责启动子代理，每个输入会话生成一个子代理做分析，每个子代理有系统提示；设计动机是保证梦境全面覆盖、不漏信息（21:41-22:10）
- 输出记忆库会创建索引文件（含未来代理可能需要的记忆文件标识），让未来代理先读索引快速定位而非广泛搜索（19:48-20:04）
- 人类可审查梦境产出（点击查看梦境任务会话，具备可观测性，便于诊断与人工审核）（17:20-17:36 / 21:18-21:24）
- 记忆库退役机制：对输出库满意后可将旧库退役，不影响旧会话，控制库数量（24:51-25:01）
- token 成本控制：设计上追求全面覆盖（token 消耗大），但大部分来自缓存（预计约 95% 缓存命中率）；另探索类似批量 API 的时间调度折扣（50%）（26:13-26:48）

### 可操作细节
- 记忆库边界由使用者自行定义：可按用户、工作区或组织创建，不限一个组织（06:09-06:20）
- 梦境任务参数：模型可选（claude 4.7 / opus / sonnet，按质量与 token 成本取舍）；输入 = 待处理记忆库 + 会话 ID 列表（可每天 10-20 个或上百个会话）（15:21-15:51）
- 梦境支持自定义指示（理想工作提示）：聚焦补充特定细节、或指定记忆库的整理结构（15:57-16:23）
- 梦境任务耗时数分钟到两小时，异步运行不阻塞（16:53-17:04）
- 记忆库管理有命令行与可视化控制台两套界面（14:08-14:12）
