## 内容提炼
### 核心论点
1. 纯向量数据库做记忆有两个致命缺陷：模糊匹配与精确调用的冲突（问预算时向量检索捞出一大堆"废话"让模型猜，而业务需要 user_budget 字段一级命中、100% 确定性）；时间盲区（用户昨天说预算 5 万、今天涨到 8 万，向量库像纸箱子里两张纸条一起被摸出，模型分不清时间先后该听谁的）（02:04-04:11）。
2. 行业标杆 ChatGPT 用极其克制的四层记忆架构：会话原数据（环境信息，用完即扔，绝不进长期记忆）/ 用户结构化档案（JSON 字段，单值覆盖，单一事实来源）/ 近期对话摘要（"前情提要"式清单）/ 滑动窗口（最老信息直接丢弃）——整个标杆系统里向量数据库完全没出场（04:18-06:25）。
3. 核心认知误区纠正：记忆系统的价值不在于存了多少数据，而在于"历史数据→当前决策"这条通道通不通（06:49-07:27）。
4. 生产级系统三件套：ledger 原始账本（像银行流水，只能追加不能修改，是出 bug 时溯源排错的黑匣子底线）+ views 派生视图（把死板底层数据加工成大模型能看的格式：知识图谱/时间线）+ policy 控制策略（整个系统的大脑：决定何时查资料、何时写记录、何时主动遗忘无用信息；没有它系统几天内变成数据垃圾场）（07:32-08:33）。
5. 显式慢思考回路：大模型本身是 System1 直觉系统；agentic memory 要把记忆读写变成 agent 可以主动调用的工具（外置机械臂），遇到复杂任务触发 System2 慢思考——先翻资料拿证据再决定回复（08:41-09:20）。
6. 时间约束的工程解法：双时间戳（每条记忆打两个时间戳：现实世界何时生效 + 何时写进系统），查询时套时间切片约束——"这是张三现在的状态，那是他过去的状态"，防止把历史当现在真相产生幻觉；很多真实场景不能直接删旧数据（张三 A 公司→B 公司，用户还会问"他去年在哪家公司"）（09:33-10:50）。
7. 程序性记忆：把一次真正成功的交互轨迹像漏斗一样过滤掉废话，压缩固化为可执行 skill（一键执行的快捷指令）；下次遇到同类 bug 不再重走痛苦流程，而是直接调那套改法——agent 有了越用越聪明的能力（10:53-12:05）。

### 关键机制
- 结构化档案（single source of truth）：明确的业务属性（职业/预算/偏好）用 JSON 字段存，喜好一变就覆盖旧值，追求 100% 精确读取，绝不模棱两可（04:56-05:20）。
- 对话摘要层：不存每一句废话，后台把聊过的主题浓缩成清单注入对话，像美剧每集开头的前情提要，无需翻所有原话记录（05:28-05:49）。
- 四层架构结论：把明确的业务属性与模糊的对话上下文彻底分开处理，系统可控性才高（06:16-06:25）。

### 可操作细节
- 记忆条目双时间戳：现实世界生效时间 + 写入系统时间（10:23-10:33）。
- skill 固化流程：成功交互轨迹→漏斗过滤废话→压缩固化→可执行 skill（11:36-11:53）。
