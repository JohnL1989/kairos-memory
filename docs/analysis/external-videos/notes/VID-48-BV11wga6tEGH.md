## 内容提炼
### 核心论点
1. Memory 不是存储，是一套由账本（ledger）、视图（views）、策略（policy）、回写（write-back）和溯源（provenance）组成的闭环（00:11-00:16）。
2. system1（快速工作的通用 agent：大模型+工具）与 system2（慢一点的外部记忆回路：保存/检索/更新/压缩/遗忘）相对正交——不是完全独立，而是工程上可以低耦合：可以换 base model 而不必重做外部 ledger/views/检索策略，同一模型接不同记忆策略长程任务表现也会变（00:32-01:52）。
3. 参数化记忆 vs 非参数化记忆：两者真正的差别不是有没有存储，而是适应算子写在哪里——参数化把成本前置到训练阶段，非参数化把成本分担到在线 commit、retrieving、inject；记忆放外部是「牺牲一点理论上限，换来可插拔、可迁移、可归因」，让长期演化可控（02:11-02:50）。
4. 外部记忆影响决策的公式：新的动作倾向 = 模型原本判断 + 记忆带来的修正量 delta（外置可控偏置，不改权重但改变动作选择）；delta 的来源必须可审计，否则系统难做 provenance、rollback 和 sandbox 对比——这也是 memory 不能只靠提示词的原因（02:52-03:22）。
5. 外部 memory 的瓶颈主要卡在三件事：接口带宽（context bridge——最朴素是 prompt 桥，更激进是 latent/KV 注入，但都有 token/延迟/显存/注意力长度预算）、检索和聚合误差（views 从 raw ledger 派生，一定是近似结构：错检、漏检、时序冲突、语义漂移）、policy 的学习与控制（写多了污染、写少了学不到；召回多了噪声、召回少了证据不够）（04:10-05:00）。

### 关键机制
- system1/system2 分工：system1 做通用推理，system2 负责长期状态；通用 agent 最贵的能力是通用性，为几条长期状态去动权重风险太大（00:57-01:20）。
- 可控交叉项：检索噪声破坏推理、错检污染答案、时序冲突把旧事实当当前事实；用 sandbox A/B 看清这些交叉项（01:53-02:09）。
- 经验迁移的两种路线：JetRL 类路线——每步行动前检索相似轨迹，用过去结果估计当前动作值不值得做，不一定要改模型参数；UMEM 类思路——按语义相似度建立「领域」，评估一条记忆对整个领域带来多少帮助，保存下来的是一类故障的处理原则而非单题答案（03:22-04:05）。
- 外部记忆不是弱化版备忘录：它追赶的是有效微调对决策产生的影响，只是把这件事放在模型外面做（04:05-04:10）。

### 可操作细节
- 决策修正 delta 示例：用户说过讨厌青椒→点餐 agent 把青椒炒肉往后排；过去部署记录显示某命令会破坏数据→系统压低它的优先级（03:03-03:13）。
- 三个瓶颈的具体内容与判断清单：接口带宽（passage/graph/skill/tool description 都要经 context bridge）、检索聚合误差（views 是近似结构）、policy 控制（写多写少的权衡）（04:10-05:00）。
- 案例可迁移性警示：只记住「这次报错要检查连接池」，明天错误信息换几个词可能就认不出来——单条案例到一类问题需要语义抽象（03:40-03:58）。

## 存疑与未验证
- 「JetRL」（音译）——每步行动前检索相似轨迹的强化学习方法，具体指哪篇论文/系统无法核实（未验证）。
- 「UMEM」（音译）——按语义相似度建领域评估记忆贡献的方法，名称无法对应到已知系统（未验证）。
- 「sandbox A B」「ledgerviews」「two description」为转写碎片，原文应为 sandbox A/B、ledger/views、tool description（未验证）。
- 本集为系列第二集，system1/system2 框架为作者自设术语（借心理学名词谈工程结构），非学界标准用法（未验证）。
- 「牺牲一点理论上限」中「理论上限」具体指什么未展开（未验证）。
