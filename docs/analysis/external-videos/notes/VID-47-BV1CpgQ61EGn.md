## 内容提炼
### 核心论点
1. Memory 不是存储：agent 记不住不等于模型不聪明，更可能是没有真正的记忆系统；AI 正从问答助手变成连工具、跑长任务的工作系统，memory 已变成「状态、偏好、经验、旧事实的治理问题」（00:07-00:30）。
2. 记忆的价值不是历史存了多少，而是「从历史到当前决策的通道有没有打通」；判断标准一句话——过去有没有帮他把今天的事做对。历史只有在当前状态下能改变动作、被选中，才真的变成能力的一部分（01:32-02:11）。
3. Memory 系统最小闭环 = Raw Ledger + Views + Policy（账本 + 视图 + 调度器）三件套；缺任何一件都不是闭环（02:36-04:01）。
4. 判断一个 memory 系统靠不靠谱，先问五个问题：原始事实在哪里？当前任务用哪个视图？谁决定读写？更新回写能不能审计？出错后能不能回放？答不上来大概率只是历史仓库（05:20-05:31）。
5. 收尾：「memory 不是存储，它是账本、视图、策略回写和溯源组成的闭环系统」（05:35-05:40）。

### 关键机制
- Raw Ledger（原始账本）：按时间顺序保留写入、修改、删除和反馈——用户哪天说了什么、系统何时改过哪条记忆、当时属于哪个任务，都要能查回来。关键提醒：账本里存的是未经美化的原始事实，不要一上来把历史压成摘要，否则后面错了证据也跟着没了（02:43-03:03）。
- Views（派生视图）：从账本加工出的可用版本——向量索引（按意思找）、全文索引（查姓名和编号）、知识图谱（查关系）、时间线（回答过去发生了什么）。视图可以压缩、可以丢细节，但必须能回到 raw ledger，否则只是「看起来很聪明却没法审计的二手结论」（03:04-03:23）。
- Policy（控制策略）：决定什么时候读、读多少、什么时候写、怎么更新、什么时候忘——是整个 memory os 的调度器。硬要求：这些决策必须显式记录成 action（ADD / UPDATE / DELETE / NONE），不能只靠 prompt 一句话暗示（03:24-03:41）。
- Ledger event 基本单位：属于哪个用户/会话/任务、发生在什么时间、当时有哪些消息和环境状态；系统动作（输出了什么、调用了什么工具、新增/更新/删除记忆）；用户反馈（评分、reward 信号）。更细还可记录决策本身：原数据候选集合是什么、命中了哪些证据、为什么提前停止检索（04:14-04:49）。
- 向量库 ≠ memory：向量库只解决一种查法，不自动处理更新、过期，也不保证来源可回放（05:10-05:17）。

### 可操作细节
- 五个评估问题清单（05:20-05:29）：原始事实在哪 / 当前任务用哪个视图 / 谁决定读写 / 更新回写能否审计 / 出错后能否回放。
- Policy action 枚举：ADD、UPDATE、DELETE、NONE 四类显式记录（03:34-03:41）。
- Event 记录字段清单：用户、会话、任务、时间、消息、环境状态、动作输出、工具调用、记忆增删改、反馈评分（04:14-04:37）。
- 决策级记录：候选集合、命中证据、检索提前停止原因（04:42-04:49）。

## 存疑与未验证
- 术语转写不稳定：raw ledger 被转写为 roll/row/leader/ladder，policy 转写为 permit、providence 等，原文应为 Raw Ledger / Views / Policy / ADD、UPDATE、DELETE、NONE（字幕错字，按上下文校正）。
- 「memory s 怎么从账本试图控制层」一句（00:45-00:50）语义不清，推测为「memory 怎么从账本、视图、控制层」一路走到工程实现（未验证）。
