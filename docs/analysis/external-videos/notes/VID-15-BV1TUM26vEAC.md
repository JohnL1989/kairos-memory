## 内容提炼
### 核心论点
1. 记忆注入方式是「工具清单+使用时机」而非「记忆原文」：系统只告诉 Agent 有哪些记忆工具、什么情况下应该检索或保存、不同类型的信息应该写到哪里——「不是一股脑把检索到的记忆都带进上下文，完整 markdown 记忆并不直接注入 prompt」（05:29-05:46）。
2. 检索结果定位为「辅助上下文，不是新的用户命令」：如果历史记忆和当前用户要求、参观文件或工具输出冲突，主 Agent 应该以当前证据为准（02:03-02:14）。
3. 分层记忆四类分工：User Memory 保存用户资料；全局+项目 Memory 保存事实、约定、踩坑经验；Session Search 检索历史对话；Skill 把已验证可重复执行的操作流程沉淀下来（08:38-09:12）。
4. 写入链路含「内容审查+范围区分」：工具请求进入拓展后先做内容审查再执行增删改，最后原子写入 markdown（用户可检查的事实来源），同时同步到 FTS5 索引；写入时区分全局/项目范围，避免不同项目之间的约定相互污染（02:31-02:51，09:06-09:12）。

### 关键机制
- 请求执行流程五步：①用户发起请求，真正理解任务的是主 Agent，拓展不代替模型处理任务（01:09-01:20）；②推理前触发 before-edit-start，注入记忆策略（记忆工具+使用时机）（01:24-01:34）；③Agent 判断是否需要历史上下文，需要则调 memory search（长期记忆）或 session search（历史对话）（01:47-02:02）；④发现值得长期保留的信息（用户信息/项目约定/踩坑经验）调 memory save，可复用的操作流程调 Skill 保存；写入先审查→原子写 markdown→同步 FTS5；核心 memory 超过容量限制时先自动整理内容再重试写入（02:18-02:59）；⑤工具把保存/检索结果反馈给主 Agent 生成最终回答（03:03-03:10）。
- Session 生命周期自动学习：检测到用户正在纠正 Agent 时尽快提取保存这次纠错；对话回合数或调用次数达到阈值后在后台复盘最近内容、提取值得长期保留的信息；每次 message end 当前 session 增量写入搜索索引；session 压缩或用户退出时执行一次 final flush 并完成最后解锁（03:24-03:52）。
- 项目级记忆写入同时补写到 ```CLAUDE.md```：把「先写测试再改实现」这类项目约定写入项目 memory，同时补充到 ```CLAUDE.md```，保持代码库的显示文档与长期记忆一致；项目记忆不是复制对话原文，而是提取后期任务真正需要遵守的约定（06:06-06:33）。
- 跨 session 用户记忆验证：新 session 问「我是谁」时，当前对话无身份信息，Agent 主动调 memory search 从磁盘持久存储重新检索，而非依赖当前 session 聊天记录假装记得（06:56-07:29）。
- Skill 与 Memory 的分工：Memory 告诉 Agent 这个项目有什么约定，Skill 告诉 Agent 遇到这类任务应该按什么流程完成；即使加载了 Skill 也仍然读取当前文件，不会盲目照搬过去步骤（08:14-08:36）。

### 可操作细节
- 安装命令：`pie install npm@pie-hermes-memory`（04:13）；命令面板 memory 命令组：memory insights（查看用户/全局/项目记忆）、memory skills（管理 skills）、memory consolidated（手动整理）、memory switch project、memory index session、memory sync markdown（初始化/迁移，自动去重，重复运行不会反复导入同一条记录）（04:27-05:22）。
- memory sync markdown 用于迁移已有记忆，内容会自动去重，不需要每次启动都运行（05:06-05:22）。
- 用「先过超市」示例项目演示：告诉 Agent 一条项目级 TDD 约定，Agent 识别为项目级信息并写入项目 memory（06:06-06:27）。
