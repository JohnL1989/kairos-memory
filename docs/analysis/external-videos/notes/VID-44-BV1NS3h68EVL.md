## 内容提炼
### 核心论点
1. 百万上下文很多时候就是一个超大的垃圾桶：用户一句、模型一句、工具日志、报错文件、网页结果全扔进去；桶快满了再叫一个模型把前半桶压成一张纸塞回桶底，循环继续（00:06 / 00:10 / 00:41）
2. 三笔账必须分开算：窗口能装多少、硬盘存了多少、模型这一轮到底看见多少；营销把它们搅成一锅统一贴上「记忆」标签——窗口再大、硬盘全存，模型眼前可能仍只有一份摘要、一节尾巴和几份离世文件（01:50 / 02:11）
3. 长上下文陷阱：模型注意力不是与输入均沾（lost in the middle，中间部分失效论文）；信息放开头/结尾还能抓住，埋进中间就像掉进注意力死区——「字都在，可是模型照样当没看见」；把窗口容量当记忆进步，就像换一张 20 米长的办公桌然后宣布员工智商提升了（02:44 / 03:11）
4. 真正的记忆不是囤积，是代谢：该沉下去的沉下去、该退出眼前的退出眼前、该在关键时刻回来的回来，回来以后还得能改变今天的判断；否则硬盘里躺着再多文档也只是档案，不是活着的历史；把每一秒原封不动钉在眼前叫监控录像，不叫理解（04:27 / 04:45 / 04:53）
5. 谁控制压缩器，谁就控制行动者的过去：OpenAI responses 远端压缩返回加密且人类不可读的压缩项、Codex 对外只留一个压缩标记和一串编号；Claude Code 相对敞开但细节活哪些、关系被抹平哪些仍难逐项验证（09:39 / 10:06 / 10:34）

### 关键机制
- 行业现状盘点（各方案逐一点评）：
  - Codex 类：系统提示词每轮重建（Agent/Identity/User 重新注入），Context 命令可查组成与 Token 占用——「规章还在，历史却没有自己的位置」；正常会话仍消息链累加，接近上限旧轮次进摘要（05:02）
  - Hermes 类：提示词装配分稳定层/上下文层/异变层；Memory 与 User 是硬上限精选集（约 1400 Token），完整会话全存本地数据库、需要时关键词回翻；但摘要器有损——摘要窗口不够时中断会被静默丢弃；每轮结束后台复盘程序重放对话、判断要不要更新记忆或技能（06:12 / 07:23）
  - OpenAI responses：远端压缩返回加密不可读的压缩项，调用方只能原样传回（09:39）
  - Claude Code：nd.json 可检查、compact 命令生成结构化摘要并登记规则、自动记忆更新注入——「一个封禁密文，一个交给摘要」（10:06）
- UP 主主张的「装配式上下文」（UPSP 项目）：把每次模型调用流成一个调用帧；调用前系统从当前帧源取材，按固定位置重新装配——永久规则、近期高频、当前状态、弹窗；每层都有来源、职责和生命周期（10:45）
- 案例对比：三天前用户决定方案甲、今天取消方案甲——垃圾式消息链把两句话一起扔给模型，谁压过谁要看位置、措辞、注意力还有运气；装配式把「已取消」写回当前帧源，下一个调用帧重新装配，当前状态进入固定位置，「决定」留在历史中但休想继续冒充现行事实（11:20 / 11:54）
- 记忆的活性定义：「决定」没有被删除，却也不再霸占现在；需要追溯时它能回来，需要行动时当前状态说了算；历史不是拖在消息链后面的一条尾巴，它得有重新参与今天判断的通道（11:54）
- 可审计性：每个调用帧留下每一层的 JSON 文件、实际请求体写入 dep JSON、发送时记录哈希——模型到底看见了什么可以逐层打开核验，有没有被调包全部摊开（12:16 / 12:45）
- 遗忘观的转变：遗忘从摘要模型的即兴表演（有损压缩的偶然结果）变成可修改、可审计、可追责的工程对象（13:23）
- 体系 vs 零件：文件注入、会话摘要、向量检索、后台记忆、长窗口全是零件；装配式上下文给它们固定位置、唯一真源和调用证据；不要求模型记住一切，要求该退出的能退出、该留下的有出处、该回来的能以正确身份回来（13:56 / 14:12 / 14:22）

### 可操作细节
- Hermes 类方案：Memory 与 User 硬上限精选约 1400 Token（06:33）
- UPSP 七层调用帧：每层 JSON 文件 + 实际请求体落盘 + 发送时哈希记录（12:45）
- 上下文分层：稳定层（永久规则）/ 上下文层 / 异变层（06:12）
