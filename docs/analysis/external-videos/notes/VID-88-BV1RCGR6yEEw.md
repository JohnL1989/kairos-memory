## 内容提炼
### 核心论点
1. 向量就是一组浮点数数组、高维空间里的一个点；向量之间的距离代表原始内容的相似程度——万物皆可向量化（图/文/视频/音频），以图搜图、人脸识别、电商拍照搜同款都是"给一个向量、从一堆向量里找距离最近的几个"（00:37-02:19）。
2. 海量向量查找不能全遍历（几千万条逐个算距离效率太低），标量数据用 B+ 树索引但向量是浮点数数组 B+ 树搞不定——需要专门的最近邻索引（02:20-03:03）。
3. HNSW（分层可导航小世界图）：参考六度人脉，把距离近的点用边连成邻居图，再分层挑稀疏节点逐层建图成金字塔；查询从最高层唯一节点开始逐层下探；快（几跳）但整张图要常住内存（03:03-04:13）。
4. IVF（倒排文件索引）：先对向量聚类，相似向量归到同一个桶（聚类中心代表整桶）；查询先算与所有聚类中心的距离锁定最近的几个桶再到桶内细找；1000 万条/1000 桶/搜 10 桶 → 候选量从 1000 万降到 10 万，计算量砍 99%（04:15-05:16）。
5. 乘积量化（PQ）：把向量分段、每段用有限数量的聚类中心编号近似替代（聚类数 ≤256 则一个字节表示一个编号）；128 维 float32（512 字节）压到两字节级（8 倍压缩）；查询时查表加加法替代逐维浮点运算（05:21-07:56）。
6. 三种索引都是近似最近邻（ANN）：HNSW 可能因图结构走弯路错过最近向量，IVF 目标向量可能落在桶边界被分到隔壁桶漏掉，乘积量化用编号代替原始值必然丢精度——允许少量误差找到足够接近结果的搜索（07:57-08:29）。
7. RAG 与 MEMORY 的本质都是向量检索：RAG 把外部知识（文档）存向量、提问时检索相关片段喂给大模型；MEMORY 把历史对话存向量、下次聊天检索最相关记忆片段塞给模型（09:00-09:31）。

### 关键机制
- HNSW 查询流程：最上层唯一节点→每层内快速锁定大致区域→越往下节点越密→最底层返回最相似结果（03:48-04:02）。
- IVF+PQ 组合：IVF 缩小搜索范围，乘积量化压缩每条向量的内存与计算量，两者组合就是 IVF-PQ（07:50-07:56）。
- 三种索引定位：HNSW 全量向量放内存主打速度优先；IVF+PQ 用精度换空间（05:26-05:32，08:31-08:37）。

### 可操作细节
- PQ 压缩比：聚类数不超过 256 → 每子段 1 字节；128 维分两段×2 字节 = 16 字节 → 2 字节（8 倍）；距离计算从逐维浮点运算（减法+乘法+加法）变为查表+加法（06:52-07:40）。
- 向量维度示例：128 维 float32 单条 512 字节，1000 万条约 5G 内存（05:31-05:38）。
