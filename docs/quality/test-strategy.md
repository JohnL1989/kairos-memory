# Kairos 测试策略

> **定位**：定义 Kairos 系统的测试分层、覆盖目标和验证方法。架构文档定义了"正确性"，本文定义"如何验证正确性"。

---

## 一、测试金字塔

```text
         ╱╲
        ╱ E2E ╲          少量端到端测试（关键路径）
       ╱────────╲
      ╱ 集成测试  ╲       中等数量（接口契约、跨层交互）
     ╱────────────╲
    ╱   单元测试    ╲     大量（各层核心逻辑、安全红线）
   ╱────────────────╲
```

| 层级 | 目标 | 工具 | 覆盖率目标 |
|:----|:-----|:-----|:---------:|
| 单元测试 | 各层核心逻辑、边界条件 | pytest + pytest-cov | ≥ 80% |
| 集成测试 | 接口契约、跨层交互、存储层 CRUD | pytest + docker-compose | ≥ 70% |
| E2E 测试 | 关键用户路径、安全红线 | pytest + docker-compose | 关键路径 100% |

## 二、单元测试

### 2.1 覆盖范围

| 组件 | 测试重点 | 边界条件 |
|:----|:--------|:---------|
| 策略层裁决器 | 帕累托计算、辞典式排序、真理模式切换 | 平局、空集、单元素集 |
| 存储层遗忘调度器 | 遗忘得分计算、潜伏势能触发、归档决策 | 得分边界值、空存储 |
| 存储层升华管道 | 四阶段状态机、门控检测、中断恢复 | 阶段跳跃、并发触发 |
| WM 层注意力调度 | 预算分配、优先级排定、容量超限背压 | 空预算、满容量 |
| WM 层模拟隔离区 | 标记隔离、置信度衰减、沙箱验证 | 冲突检测、超时 |
| 元认知层检测器 | 偏置阈值触发、告警路由、降级信号 | 阈值边界、毛刺过滤 |
| 宪法主权面 | 冻结/解冻、校准信号注入、虚拟校准 | 并发冻结、超时解冻 |

### 2.2 安全红线验证（P0）

19 条安全红线（S-01~S-19）每条至少一个单元测试：

| 红线 | 验证方法 | 通过条件 |
|:----|:--------|:---------|
| S-01 | 无 Key 启动 | 拒绝启动（API Key 哈希存储 + 启动时校验） |
| S-02 | 超限写入 | 返回 429 |
| S-03 | 超长输入 | 返回 413 |
| S-04 | 非本机请求 | 拒绝 |
| S-05 | 无盐值启动 | 拒绝启动 |
| S-06 | 越权操作 | 返回 403 |
| S-07 | 敏感信息加密与脱敏 | 写入时 AES-256-GCM 加密存储，导出时掩码脱敏；敏感信息导出→脱敏后输出 |
| S-08 | 未授权管理访问 | 拒绝 |
| S-09 | 常驻契约写入前注入扫描（prompt injection / 角色劫持 / 后门 / 隐形 Unicode） | 拒绝写入，记录告警 |
| S-10 | 见证豁免绕过 | 身份记忆保留 |
| S-11 | 自校准修宪 | 被拒绝 |
| S-12 | 探索计入使用排序 | 被拒绝 |
| S-13 | 模拟产物转正 | 被拒绝 |
| S-14 | 权重写回见证 | 被阻止 |
| S-15 | 来源缺失写入 | 返回 422 |
| S-16 | 定向遗忘未留痕 | 视为未执行 |
| S-17 | 结构性反例免于遗忘 + 法定擦除例外 | 标记 is_structure=true 的记忆不进入遗忘调度评估；对 is_structure 记忆执行定向遗忘操作→宪法主权面拒绝并告警（架构 §8 S-17 两层语义）；**法定擦除例外**：外部法律强制擦除（GDPR / 个人信息保护法等）命中 is_structure=true 记忆时不走常规定向遗忘路径，改由 S-19 哈希净化执行（保留结构位点维持推理拓扑），须经宪法解释层单独裁定并以 `statutory_erasure` 留痕（安全规格 S-17 法定擦除例外条款） |
| S-18 | Hard Delete 安全门 | 硬删除前检查 vector 清理 → vector 已清理方可删除 |
| S-19 | 哈希净化 | 定向遗忘后查 DB → 原文被 SHA-256 替代（内容层）；行为层无痕另行验证，见 §2.2a |

#### 2.2a 遗忘生效验证（S-16 / S-19 的补充验收）

架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §8「遗忘生效验证」对 S-19 与定向遗忘设定三项补充约束，验收载体如下：

| 编号 | 验证项 | 方法 | 通过条件 |
|:----|:------|:-----|:---------|
| TC-S19-002 | 遗忘生效三样本检验 | 对执行遗忘的记忆做三样本对比——遗忘模型 vs 安全重训模型 vs 原始缺陷模型，比较检索/生成行为分布 | 遗忘后行为更接近安全重训模型；若仍贴近原始缺陷模型则判定遗忘未生效 |
| TC-S19-003 | 双副本遗忘完备性测试 | 遗忘后分别检查见证主副本与使用影子副本——查主副本原文哈希化、查影子副本可检索权重/嵌入残留（检索路径抑制器 §5.2 与 S-19 联动） | 两层同时生效；仅主副本净化而影子副本残留可检索权重/嵌入 → 判定遗忘不完备 |
| TC-S19-004 | 「内容不可恢复 ≠ 行为无痕」边界断言 | 检查激活权重、热度轨迹、嵌入相似度是否残留可观测影响 | 行为层无痕未经本项验证前，文档与产品话术不得宣称「无痕遗忘」；仅可声明「内容不可恢复」 |

> **边界**：Kairos 只在检索路径与存储内容两个位置操作知识控制，不做参数级（模型权重）操作——参数位置属模型训练方职责，不纳入本项验收范围（架构 §8 知识控制三位置路由粒度对照表）。

### 2.7 反事实检验验证（学习效果评估）

> **外部理念吸收注记**：判断 Agent 是否真学会了，须「拿走历史上下文、只保留系统声称已学到的东西，改善是否仍然存在」（反事实检验）；只展示第二次成功了远远不够（可能只是答案缓存或上下文续写）。本用例为 [acceptance-criteria.md](acceptance-criteria.md) §一a「任务成功率改善」指标的测量载体。

**三态对比设计**：同一任务集（与记忆经验来源**分离**的独立验证集，见 [benchmark-plan.md](benchmark-plan.md) §3.11 基准设计红线）分别以三种模式运行，对比任务成功率：

| 模式 | 输入 | 判读 |
|:----|:----|:-----|
| A 完整上下文 | 检索记忆 + 当前上下文（生产形态） | 上限参照 |
| B 仅检索记忆 | **移除历史对话/轨迹上下文**，仅注入记忆系统检索产物 | 反事实检验——「已学到的内容」是否独立支撑能力 |
| C 无记忆 | 无检索产物，仅当前上下文 | 基线参照 |

**通过条件**（对应 acceptance-criteria §一a 语义）：
- 记忆有效：B 相对 C 的任务成功率净改善 ≥ 10%（设计目标，首轮基准后校准）
- 记忆与上下文互补：A > B ≥ C
- **伪持续学习判定**：B ≈ C（无显著改善）→ 记忆只是「上下文续写型」（历史仍在窗口里时有用，拿走即失效），触发记忆质量审查（检查写入/巩固环节是否产生了可复用经验，而非原始轨迹堆积）

**用例编号**：归入 E2E 扩展——`TC-CF-001`（冷启动无记忆基线）、`TC-CF-002`（仅检索记忆反事实态）、`TC-CF-003`（完整上下文态）、`TC-CF-004`（新任务泛化——验证集使用未在经验来源中出现过的任务，防评测泄漏）。

**前置条件**：任务成功率信号由外部 Agent 集成层回传——契约见 [integration-design.md](../development/integration-design.md) §五a（`task_outcome` 事件，三态 `mode` 字段）；无集成环境时该用例标记 `skipped`，不影响竖切验收（竖切验收不设学习效果指标）。

| 测试 | 验证内容 |
|:----|:---------|

### 3.2 跨层交互

| 测试 | 涉及层 | 验证内容 |
|:----|:------|:---------|
| WM→存储→策略 检索 | 3 层 | 检索请求经事件总线路由，结果正确返回 |
| 校准信号→主权面→全层 | 2+ 层 | 校准信号到达后见证锚定更新 |
| 冻结→主权面→全层 | 2+ 层 | 冻结后所有内部环暂停生成性操作 |
| 降级模式切换 | 3+ 层 | 外部校准中断后状态机按契约切换 |

### 3.3 事件总线集成

- 事件发布 → 订阅 → 消费 → ACK 全链路
- 背压测试：事件生成速率超过消费速率 → 背压触发 → 限制上游
- 优先级测试：高优先级事件应优先生效

## 四a、契约验证方法论（外部理念吸收 0.0.44；外部实证：PAPER-06 REMIT）

> **39 格故障矩阵 + 属性独立性方法**：契约属性逐条独立验证（consume-once 的独立性发现——REMIT 证明各属性可在不依赖其他属性的前提下独立成立/失败）——纳入本策略作为契约验证方法论：对恢复契约六属性（前缀延续/效果恰好一次/分叉确定性/检查点有效性/消费一次/恢复确定性）按「属性 × 故障注入」矩阵逐格验证（6 属性 × 中断/崩溃/重放/并发/部分写入/时序错乱等故障类），每属性独立判定，不因其他属性通过而跳验。
>
> **版本固定纪律**：LLM-free 确定性 harness + pinned release 实测方法，纳入质量门禁对依赖框架（若有）的验证流程——依赖版本固定 + 确定性复现，防「升级即行为漂移」。

## 六、配置集测试矩阵与证伪测试

### 6.1 配置集测试矩阵

架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §0.8 规定：三种命名配置集是唯一受支持的编译形态，**测试矩阵只对这三种配置集负责，未命名组合不进入测试与验收范围**。矩阵定义如下（配置集的标志构成以架构 §0.8 为权威，本表不重复）：

| 配置集 | 单元测试 | 集成测试 | E2E | 定位 |
|:------|:--------|:--------|:----|:-----|
| `kairos-minimal` | 核心组件子集（统一 LTM / 路径空间 / 三信号检索 / 身份注册表 / 基础审计日志） | 存储层 + 检索链路 | 冒烟集（写入→检索） | 最小系统原型回归；降级阶梯末级形态 |
| `kairos-slice` | 竖切组件全集（见 [slice-implementation-guide.md](../development/slice-implementation-guide.md)） | 竖切内组件间接口 | **7/9 条**（E2E-01/02/04/05/06/07/08；E2E-03 升华与 E2E-09 S-14 不在竖切范围） | **竖切首交付的验收形态** |
| `kairos-full` | 全部 ≥70 个组件路径 | 全部 ≥12 组接口 | **9/9 条**全通过 | v0.1.0 完整交付门禁 |

**矩阵纪律**：

- 未命名标志组合不建用例；CI 中以 `kairos-slice` 为默认执行形态，`kairos-minimal` 与 `kairos-full` 在发布前全量执行。
- 三配置集均须通过启动校验用例——组合合法时正常启动，人为构造未命名组合时断言拒绝启动并输出 `invalid_flag_composition`。
- 宪法核校验用例：断言 `NARRATIVE_IDENTITY` 关闭时系统输出 `constitutional_core_unavailable` 并拒绝启动（门控优先级规则 (c)）。

### 6.2 证伪测试

架构 §0.8 编码纪律要求「每次打开一个新特征标志，第一件事是写它的证伪测试」「没有证伪测试的特征标志不应合入主分支」。

- **标记约定**：`@pytest.mark.falsification`，测试名前缀 `test_fal_`，报告中归入 `[FALSIFICATION]` 分组，与功能测试同套件并行执行。
- **断言目标**：不是「功能可用」，而是「假设被证明错误时系统承认失败」——即假设状态是否正确切换为 `challenged` / `false`，以及是否执行了架构 §0.8 规定的对应处置。
- **三类失败路径的断言**（与架构 §0.8 三分支一一对应）：

| 假设类型 | 绑定标志 | 断言处置 |
|:--------|:--------|:--------|
| 非核心假设 | 其余 9 个标志 | 标记 `experimental: degraded` + 日志告警，标志保持原状态 |
