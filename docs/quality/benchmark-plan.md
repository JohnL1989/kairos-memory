# Kairos 性能基准计划

> **定位**：定义性能测试方法、数据规模和硬件基线。NFR 定义了「目标值」，本文定义「如何测出目标值」。

---

## 一、测试环境基线

基线定义：首次运行基准测试套件时的性能快照，记录于 `reports/benchmark-baseline-{version}.json`。基线的快照时机为每次 MINOR/PATCH 版本发布前的最后一次基准运行。复算方式：在相同硬件上重新运行基准套件，输出与基线比对。

| 硬件 | 规格 |
|:----|:-----|
| CPU | 4 核 x86_64（标准模式）/ 2 核（轻量模式） |
| 内存 | 8 GB（标准模式）/ 2 GB（轻量模式） |
| 磁盘 | SSD, 50 GB 可用（标准模式）/ 10 GB 可用（轻量模式） |

## 二、测试数据规模

| 测试级别 | 记忆数 | 说明 |
|:--------|:------:|:-----|
| 竖切档 | 10,000 | **竖切（v0.1.0-slice）验收基准**（轻量模式 SQLite，对应 acceptance-criteria 性能基准） |
| 小规模 | 1,000 | 功能验证 |
| 中规模 | 50,000 | 典型使用场景 |
| 大规模 | 500,000 | 压力测试（标准模式，PostgreSQL） |
| 极限 | 1,000,000 | 容量边界验证（标准模式，PostgreSQL） |

## 三、测试方法

### 3.1 写入延迟

> **通过/失败判据**：P50 ≤ 50ms, P95 ≤ 200ms（NFR 规格 §一）

```text
1. 预热：写入 1000 条记忆
2. 测量：逐条记录写入延迟（连续写入 10000 条）
3. 统计：P50/P95/P99
4. 变量：内容长度（256B/1KB/8KB）、嵌入维度、索引类型
```

### 3.2 检索延迟

> **通过/失败判据**：路径前缀检索 P50 ≤ 20ms、P95 ≤ 80ms；语义检索 P50 ≤ 100ms、P95 ≤ 300ms（NFR 规格 §一）。竖切验收按「竖切档 10,000」取数。

```text
1. 准备：写入 N 条记忆（N=10000/1000/50000/500000）
2. 测量：随机选取 1000 条已知路径进行路径前缀检索
3. 测量：随机选取 1000 条记忆进行语义检索
4. 统计：P50/P95/P99
5. 变量：存储规模、向量索引类型（IVFFlat/HNSW）、probes 参数
```

### 3.3 吞吐量

> **限流说明**：以下测试中并发 10/50/100 个客户端为基准负载模型，非生产限流配置。基准测试期间应临时调高 `KAIROS_RATE_LIMIT_WRITE_PER_MIN` 和 `KAIROS_RATE_LIMIT_READ_PER_MIN` 至无限制（如设为 100000），测试完成后恢复原值。详见 [ops/configuration.md](../ops/configuration.md) §7。单客户端写入默认限流 60/min、读取默认限流 120/min 与 100 并发不矛盾——并发 = 独立客户端数，限流 = 每客户端速率。

```text
1. 准备：写入 50000 条记忆
2. 写入吞吐：并发 10/50/100 个客户端，持续 60s
3. 检索吞吐：并发 10/50/100 个客户端，持续 60s
4. 混合负载：70% 检索 + 30% 写入，持续 120s
5. 统计：平均吞吐量 + P95 延迟
```

### 3.4 升华批处理

> **通过/失败判据**：升华批处理（单条 raw→behavior 全阶段，不含人工审批等待）P50 ≤ 30s、P95 ≤ 120s（NFR 规格 §一）

```text
1. 准备：选中 100 条记忆进入升华队列
2. 触发：强制触发升华（跳过空闲检测）
3. 计时：从 raw 阶段开始到 behavior 阶段产出
4. 统计：平均完成时间 + 各阶段耗时分布
```

### 3.5 磁盘增长

> **通过/失败判据**：10 万条写入后磁盘占用 ≤ 2GB（标准模式）/ ≤ 500MB（轻量模式）（NFR 规格 §四 磁盘 10 万条口径）；磁盘可用空间不低于部署预算（标准模式 50GB / 轻量模式 10GB，NFR 规格 §二）；年增长 ≤ 2GB（10 万条/月写入速率，NFR 规格 §四）

```text
1. 初始：记录空库磁盘占用
2. 写入：每写 10000 条记录一次磁盘占用
3. 触发升华：记录升华后的磁盘变化
4. 触发遗忘：记录遗忘归档后的磁盘释放
5. 绘制：写入量 vs 磁盘占用曲线
```

### 3.6 可用性与故障恢复

> **通过/失败判据**：自动恢复 RTO ≤ 30s（P95）。**可用性说明**：10 次重复试验不足以统计证明 99.9% 可用性（n=10 全成功时 95% 置信下限约 74%）。本测试验证恢复机制正确性（数据完整率 100%）和恢复时间，可用性声明以生产运行数据为准。

```text
1. 正常写入 100 条记忆
2. 模拟进程崩溃（kill -9 主进程）
3. 计时：从崩溃到 API 恢复可用（/health 返回 200）
4. 验证：恢复后检查写入数据完整性（未丢失已持久化数据）
5. 统计：10 次重复试验的 P95 恢复时间 + 数据完整率
```

### 3.7 多路径融合延迟

> **通过/失败判据**：P50 ≤ 50ms, P95 ≤ 150ms（NFR 规格 §一）

```text
1. 准备：写入 10000 条记忆（各含路径/语义/关系三种索引）
2. 触发：随机选取 100 条 query，执行多路径检索（路径+语义+关系）
3. 计时：三路径结果集汇聚→交集计算→融合排序全链路
4. 统计：P50/P95 融合延迟
```

### 3.8 遗忘扫描延迟

> **通过/失败判据**：10 万条全表扫描 ≤ 60s（[nfr-specification.md](../specification/nfr-specification.md) §一 性能）

```text
1. 准备：写入 100000 条记忆（含不同过期时间）
2. 触发：强制遗忘扫描（跳过空闲检测直接执行）
3. 计时：全表扫描完成时间（不含实际删除操作）
4. 统计：扫描时间 + 标记为可遗忘的记忆数
5. 变量：存储规模（1万/5万/10万）
```

### 3.9 资源占用基线

> **通过/失败判据**：24h 稳态下**空闲态内存占用 ≤ 256 MB**（含 LLM 缓存；内核级（轻量模式）≤ 64 MB），全负载进程常驻 ≤ 1 GB（内核级 ≤ 256 MB），CPU ≤ 5%（空闲态）（[nfr-specification.md](../specification/nfr-specification.md) §四）
>
> **口径提示**：本项度量的是**进程内存占用的上界**，不是"可用空闲内存的下界"。占用越低越好。

```text
1. 初始：记录空载资源（CPU、RSS、堆外内存）
2. 写入负载：连续写入 10000 条记忆，记录峰值资源
3. 空闲稳态：停止负载后持续观测 30 分钟
4. 检索负载：连续检索 1000 次，记录峰值资源
5. 统计：各阶段的平均 CPU / 内存 / 峰值
```

### 3.10 启动时间

> **通过/失败判据**：标准模式启动 ≤ 10s（NFR 规格 §三）。全量模式 ~15 秒为扩展设计值（NFR 仅定义标准模式启动时间目标，见 [deployment.md](../ops/deployment.md) §一）

```text
1. 准备：标准模式 compose 环境（数据库连接就绪）
2. 测量：进程启动到 /health 返回 ok 的时间（`docker compose up -d` 后轮询健康检查）
3. 统计：10 次冷启动的 P50/P95
4. 变量：冷启动（清空缓存）/ 温启动（复用缓存）
```

### 3.11 基准设计红线：经验来源与验证数据分离

> **外部理念吸收注记**：本红线吸收自外部对「伪持续学习」的分析（2026-07）——**评测泄漏**（同一批任务既用于总结经验、又用于证明能力提升）是伪持续学习的第四种形态：从任务集 A 总结经验，再用任务集 A 证明能力提升，改善是循环论证而非真实学习。

**红线规则**：凡涉及「记忆/经验对任务表现的影响」的基准与验收（含 §2.7 反事实检验、acceptance-criteria §一a 任务成功率改善指标），必须满足：

1. **验证集分离**：验证任务集与经验来源任务集**无重叠**（任务标识符集合交集为空；同一任务变体——仅改参数/文案/域名——视同重叠，须排除）。
2. **时间分离**：验证任务的经验积累时间窗与验证执行时间窗不重叠（先积累后验证，禁止边验证边积累）。
3. **声明义务**：基准报告须显式声明「验证集与经验来源无重叠」及核验方法（如任务标识符集合比对结果），未声明即视为不满足红线。
4. **受控条件**：验证任务的未来形态未在经验来源中「原样出现过」——agent 获得的只是经允许的经验，改善须能被外部独立验证。
5. **简单基线对照**：凡记忆机制有效性基准，须含简单基线对照（无记忆 / 词法检索 BM25 / 嵌入检索），报告显式对比并声明记忆机制的增量价值；未对照即视为不满足红线（外部实证：PAPER-17 MemoryBench——高级记忆框架一般无法一致超越简单 RAG 基线，ICML 2025，第三方口径）。

**适用场景**：本节红线仅约束「学习效果类」基准；性能基准（§3.1~§3.10 延迟/吞吐/资源）不涉及经验复用，不受本节约束。

> **能力验证门方法论注记（外部理念吸收 0.0.48；外部实证：PAPER-21 MemEye 消融四验证门）**：MemEye 为每个基准任务构建消融驱动验证门——**可答性**（问题确实可答）/ **捷径抗性**（无法用捷径/文本痕迹猜答）/ **必要性**（确实需要目标证据）/ **推理结构**（确实需要目标推理形态），确保「测的是想测的」。Kairos 基准任务验收补充该方法论：新增任务用例须声明四门核验方式（文本域适配映射：事实级/语义级证据粒度 × 单用/合成使用方式），与本节的简单基线对照红线配套；多模态场景为 v1.1 参考（MemEye/MIRIX/Mem-W 同域，Kairos 文本定位不变）。

### 3.12 六梯度消融实验方法论（外部实证：文件系统记忆论文 VID-56）

> **外部实证来源**：文件系统记忆论文 VID-56——真实使用中「分类整理」（路径归类/标签/分组）与「内容修改」（摘要/改写/归一化）两类写入加工相互混杂，质量变化无法归因；消融分离后才能回答「检索质量变化来自哪个操作面」。

**设计**：以「分类整理」与「内容修改」两轴叉乘构成六梯度，同一评测任务集（验证集须遵守 §3.11 经验来源与验证数据分离红线）逐梯度度量：

| 梯度 | 分类整理 | 内容修改 | 对照意义 |
|:--|:--|:--|:--|
| G1 | 无 | 无 | 原始基线——写入原样，隔离存储与检索自身损耗 |
| G2 | 仅路径归类 | 无 | 分类整理独立贡献（隔离内容修改影响） |
| G3 | 归类 + 标签 | 无 | 分类整理上限（标签增量） |
| G4 | 无 | 摘要 + 改写 | 内容修改独立贡献（隔离分类整理影响） |
| G5 | 路径归类 | 摘要 + 改写 | 常规组合 |
| G6 | 归类 + 标签 | 摘要 + 改写 | 完整加工上限 |

**度量与判定**：逐梯度执行检索精度（任务感知评分，见 [detailed-design.md](../specification/detailed-design.md) §10.2）与过时调用率（见 [acceptance-criteria.md](acceptance-criteria.md) 记忆质量评估指标）比对；相邻梯度差异须达统计显著（p < 0.05）才计入结论。若 G1→G2 无显著差异，说明分类整理收益可忽略（可简化加工管线）；若 G4 相对 G1 显著下降，说明内容修改环节引入信息损失（与 [troubleshooting.md](../ops/troubleshooting.md) 记忆整合失效排查联动）。

### 3.13 检索回归基准建议：InMind 125 任务（外部实证：PAPER-02，2026）

> **外部实证来源**：PAPER-02（2026）——InMind 基准包含 **125 个任务**，聚焦**隐式关联**（implicit associations）：查询与目标记忆无语面（关键词）重叠、仅存在语义/经历层面关联。此类关联恰是三信号检索（语义 + BM25 + 实体，架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §7.3a）最易丢失的一类——BM25 与实体信号依赖显式重叠，隐式关联仅由语义向量通道承载。

**建议**：检索回归基准在既有语料规模档（§3.2）之外引入 InMind 125 任务作为**补充回归套件**——125 个隐式关联用例度量语义通道对「无显式重叠关联」的召回，防止回归测试只覆盖显式关键词重叠场景、语义通道退化无感。

**落地口径**：建议项（非硬性发布门槛）——基准套件搭建时收录隐式关联用例 ≥ 30 个；回归阈值沿用 §四 统计方法（10 次重复 P50/P95，异常值剔除后补测）。

> **间接查询入测注记（外部理念吸收 0.0.44；外部实证：PAPER-02 InMind 信任悖论）**：Kairos 验收不得只测直接查询——**间接查询（跨域关联）须进检索链路测试集**：外部实证显示显式关联检索 84% 命中 vs 隐式关联仅 14.4%（检索假设被证伪：查询语义相似 ≠ 所需记忆），只测直接查询会系统性高估检索质量。落地：§3.13 的 125 任务套件即为间接查询承载（与本节一致），新增用例时同步登记来源（外部实证标注）。

> **长上下文问答基准参考注记（外部理念吸收 0.0.44；外部实证：PAPER-03 Zero-Mem / PAPER-05 ACM）**：长上下文问答基准参考——LoCoMo + 448K 长上下文 HotpotQA 改造（PAPER-03 基准方法）；Compaction 质量对标参考值 LongMemEval 92% / LoCoMo 93.2%（PAPER-05 Maximem Synap，**参考非门槛**）。评估维度缺口补录：latency / token 效率 / context-rot 抗性三维度纳入评估维度清单（CRI 维度 Kairos 已承载）。参考值须经本地校准后方可作门槛（外部实证标注）。

> **用户反馈模拟评估维度注记（外部理念吸收 0.0.48；外部实证：PAPER-17 MemoryBench 用户反馈模拟框架）**：以「服务期用户反馈累积 → 留出测试性能提升」度量持续学习——任务提供器（(q,v,c) 案例 + 3 域双语约 2 万案例）+ 用户模拟器（显式评分 0–9 + 隐式动作 + 终止信号）+ 性能监视器（LLM-as-judge）；四协议覆盖批量重放/流式重放/在线/训练重测（灾难遗忘检测）。Kairos 基准补充评估维度：① 用户反馈模拟（LLM-as-user 模拟与真实反馈的差距须标注）；② 四协议中的训练重测对应整合回归测试（PAPER-01 注记，见 §3.12 相关）；③ 声明性/程序性记忆分型度量——与「系统存事实易、从反馈改行为难」的外部实证（程序性知识缺口）衔接 D-427 研究议程。

### 3.14 任务感知评分评估流程（0.0.42 自 detailed-design §10.2 承接）

任务感知评分（Task-Aware Precision@K / MRR）的基准评估流程（评分协议定义见 [detailed-design.md](../specification/detailed-design.md) §10.2，时序参数见 [acceptance-criteria.md](acceptance-criteria.md) §三）：

1. 以时间点 T 执行查询 Q，记录检索结果 R（top-K，K 可配置）
2. 对 R 中每条记忆计算 `task_score`（相对于期望答案集 A 中的对应条目）
3. 聚合得分：
   - **Task-Aware Precision@K** = Σ(task_score(r) for r in R) / K
   - **Task-Aware MRR** = max(task_score(r) for r in R) / rank_of_max
4. 传统 Precision@K 和 MRR 同时计算（作为对照组）——用于量化评分协议的改进幅度

## 四、性能回归阈值

> **统计方法**：所有延迟指标取 10 次重复试验的 P50/P95/P99。单个异常值（Q3+3×IQR）剔除后补测。吞吐量指标取 60s 稳态窗口的移动平均值。

| 指标 | 回归阈值 | 说明 |
|:----|:--------:|:-----|
| 写入延迟 P50 | 超过基线 50% | 触发告警 |
| 检索延迟 P50 | 超过基线 100% | 阻塞发布 |
| 吞吐量 | 低于基线 30% | 触发告警 |
| 多路径融合 P50 | 超过基线 50% | 触发告警 |
| 故障恢复 RTO | > 30s | 阻塞发布 |
| 遗忘扫描（10万条） | > 60s | 触发告警 |
| 内存泄漏 | 连续 24h 增速 > 1%/h | 阻塞发布 |
| 空闲 CPU | > 5% | 触发告警 |
| 轻量模式 CPU 均值 | ≤ 2%（基准：竖切档 10,000） | 超过即触发告警 |
| 空闲态内存占用 | > 256MB | 触发告警 |
| 磁盘增速 | 超过预期 100% | 触发告警 |
