# Kairos 测试计划

> **定位**：v0.1.0 核心路径与边界用例的具体定义。与 [test-strategy.md](test-strategy.md)（方法论/金字塔）互补——策略说"怎么测"，本文件说"测什么"。
>
> **代码启动前**应完成核心路径用例定义（TC-* 的输入/预期输出/边界条件），按 TDD 或 test-first 方式驱动实现。具体用例数待代码启动后根据实际接口数量确定。

---

## §1 测试范围

### v0.1.0 核心覆盖

| 层级 | 覆盖目标 | 用例数 |
|:----|:--------|:-----:|
| 单元 | 各组件核心函数（存储/WM/策略/宪法主权面） | **下界 ≥ 70**（[implementation-map.md](../specification/implementation-map.md) 登记 70 个组件路径，每组件至少 1 条；精确值随实现接口数确定） |
| 集成 | 组件间接口（WM↔存储、PM↔存储、主权面↔PM） | **下界 ≥ 12**（六层栈相邻层接口 5 组 + 监督平面 3 组 + 跨层旁路 4 组，每接口至少 1 条） |
| E2E | 9 条关键路径（写入→检索→遗忘→升华→校准→审计→冷启动→中断降级→S-14） | 9 |
| 安全 | 19 条安全红线逐条验证 | 19 |
| 迁移 | DB schema 迁移（补充，对齐 project-plan W2「迁移可回滚」与 reliability 数据库回滚策略） | ≥ 3（正向迁移/回滚/幂等重放各 1） |
| 回滚 | 记忆版本回滚 + 压缩回滚（补充，对齐 api-spec §1.4 rollback/versions 端点） | ≥ 2（记忆回滚、compaction 回滚各 1） |

### 不覆盖

- UI 测试（无图形界面）
- 性能基准（由 [benchmark-plan.md](benchmark-plan.md) 覆盖）
- v1.1+ 功能（社会性校准等）——定向遗忘的安全红线验证（S-16/S-19）归入 §3.8 红线测试，不视为功能级定向遗忘测试

## §2 进入/退出准则

| 准则 | 条件 |
|:----|:-----|
| **进入**（何时开始测） | 核心组件接口稳定、DB schema 已迁移 |
| **退出**（何时算测完） | 单元覆盖率 ≥80%、9 条 E2E 全通过、19 条安全红线逐条验证通过 |
| **暂停** | 阻塞性 P0 bug 未修复时暂停 E2E，修完继续 |

> **E2E 竖切对照注记（补充）**：竖切验收门禁为 **7/9 条 E2E**（E2E-01/02/04/05/06/07/08 通过；E2E-03 升华、E2E-09 S-14 不在竖切范围，见 [acceptance-criteria.md](acceptance-criteria.md) 竖切判据与 [project-plan.md](../governance/project-plan.md) W10）——「9 条全通过」为 v0.1.0 完整交付门禁，竖切阶段执行 7/9 口径。

## §3 核心路径用例（代码启动前）

### 3.1 写入（W-01 ~ W-07）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-W01-001 | 系统运行 | `kairos write kairos://test/greeting "hello"` | 路径+内容 | 返回路径 `kairos://test/greeting` |
| TC-W01-002 | 已有一条 W-001 | 路径前缀检索 `kairos://test/` | 检索参数 | 返回包含该记忆的列表 |
| TC-W01-003 | 无 Key 状态（运行时） | `curl -X POST /v1/memories` | 无 Authorization | 401（启动级无 Key 为连接被拒绝，属 S-01 启动拦截；运行时缺 Key 返回 401） |
| TC-W02-001 | 系统运行 | 指定 `contract=permanent` 写入 | 常驻契约 | 遗忘调度器扫描 10 轮后该记忆仍存在 |
| TC-W04-001 | 系统运行 | 写入时附带 VAD `{"v":0.5,"a":0.3,"d":0.8}` | VAD 元数据 | 检索结果中包含 VAD 字段 |
| TC-W07-001 | 系统运行 | 写入含敏感模式内容（如 API Key） | 敏感内容 | DB 中该字段为密文 |
| TC-W03-001 | 系统运行 | `POST /v1/memories/batch` 提交 5 条批量导入（补充，竖切功能 W-03） | 批量 JSON（含 episodes 数组） | 全部写入成功；`node_episode_index_map` 归因正确；单条失败不影响其余 |
| TC-W03-002 | 批量导入含 1 条触发捕获门控的条目 | 同上（该条目含 `api_key=` 模式） | 批量 JSON | 敏感条目被拒绝（S-07）并标记 `capture_rejected`，其余条目正常写入 |

### 3.2 路径检索（R-01）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-R01-001 | 路径下有 10 条记忆 | `kairos search --path kairos://test/` | 路径前缀 | 返回该路径下全部 10 条 |
| TC-R01-002 | 路径不存在 | `kairos search --path kairos://nonexistent/` | 不存在路径 | 返回空列表，非 404 |
| TC-R01-003 | 路径为空 | `kairos tree` | 空路径 | 显示空目录树 |

### 3.3 语义检索（R-02）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-R02-001 | 写入 3 条相关记忆 | `kairos search "query text"` | 查询文本 | 返回按相似度排序的 Top-K |
| TC-R02-002 | 无匹配 | 检索完全不相关内容 | 无关查询 | 空列表（或最低相似度项） |

### 3.4 多路径融合检索（R-03）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-R03-001 | 同一主题写入 3 条记忆，分别只能由路径前缀、语义相似、全文关键词命中 | `POST /v1/memories/search`（多路径融合，含语义 + 全文检索） | 融合查询 | 三条全部召回；结果按融合分排序，同一记忆不重复出现（去重生效） |
| TC-R03-002 | 三路召回结果存在交集 | 同上，并比对单路检索结果 | 融合查询 | 融合分 = 三信号加权（默认 0.50/0.35/0.15）；交集项排名不低于其在任一单路中的排名 |

### 3.5 遗忘与复兴（F-01 ~ F-03）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-F01-001 | 写入 1 条临时契约记忆 | 等待遗忘调度器运行 N 周期 | — | 被标记为遗忘候选 |
| TC-F02-001 | 1 条低使用记忆 | 手动触发潜伏重估 | 重估信号 | 记忆被重估，保留或归档 |
| TC-F03-001 | 已归档记忆 | 触发潜伏势能重估（latent_trigger 盲区命中）或注入外部校准信号 | 重估信号/校准信号 | 记忆复兴（Archived→Active），回归可用状态（勘误：复兴由潜伏势能重估/外部校准触发，非显式检索） |

### 3.5a 记忆管理（M-01 ~ M-05，竖切）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-M03-001 | 系统运行 | `kairos forget {id}`（显式遗忘，竖切功能 M-03——标记遗忘候选，语义见 [api-spec.md](../specification/api-spec.md) §3） | 记忆 ID | 记忆被标记为遗忘候选（forgetting_queue 新增记录），数据保留、不立即删除（由遗忘调度器后续处理）；S-16 定向遗忘留痕适用于抑制/删除类操作，不适用于候选标记（见架构 §8 S-16） |
| TC-M05-001 | 1 条低使用记忆 | `POST /v1/memories/{id}/archive`（归档，补充，竖切功能 M-05） | 记忆 ID | 记忆进入冷存储，常规检索不再返回；`restore` 后恢复可检索 |

### 3.6 校准与降级（CAL-01 ~ CAL-06）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-CAL01-001 | 系统运行 | `POST /v1/calibrate` | 校准信号 | 见证锚定更新 |
| TC-CAL02-001 | 系统运行 | 提交宪法条目变更 | 宪法变更请求 | 变更进入待审批态，未经批准不生效 |
| TC-CAL03-001 | 系统运行 | `kairos freeze` | 冻结命令 | 内部环暂停，冻结状态查询返回 frozen |
| TC-CAL04-001 | 系统运行 | `kairos degradation switch --mode safe_hibernation` | 降级命令 | 系统进入安全休眠态，仅保留基本存取 |

> **命名约定**：测试用例统一采用 `TC-<功能编号去横线>-NNN` 三段式，其中功能编号取自 [feature-list.md](../specification/feature-list.md)。校准类功能编号为 `CAL-01~CAL-06`，故用例编号为 `TC-CAL01-001` 形式。**旧写法 `TC-C01-001` 已废弃**（C 前缀属 claim-implementation-matrix 的架构承载声明命名空间，不得复用于测试用例）。

### 3.7 E2E 关键路径（9 条）

| ID | 路径 | 用例 |
|:---|:-----|:----|
| E2E-01 | 写入→检索 | 写入 3 条记忆，路径检索和语义检索均确认存在 |
| E2E-02 | 写入→遗忘→复兴 | 写入→等待遗忘→确认归档→触发潜伏势能重估（或注入校准信号）→确认复兴（勘误：复兴触发源为潜伏势能重估/外部校准，非显式检索） |
| E2E-03 | 写入→升华 | 写入→空闲触发升华→查询升华状态→确认 raw→item 升格 |
| E2E-04 | 校准→见证更新 | 注入外部校准信号→确认见证锚定更新→检索含新锚定值 |
| E2E-05 | 冻结→恢复 | 冻结系统→确认不可写→解冻→确认可写 |
| E2E-06 | 审计链验证 | 写入→修改→删除→查询审计日志→验证 HMAC 链完整性 |
| E2E-07 | 冷启动→写入→检索 | 启动系统→注入种子→写入 3 条记忆→路径和语义检索确认存在 |
| E2E-08 | 外部校准中断→降级 | 中断校准信号→观察降级状态机按预设周期切换 |
| E2E-09 | 安全红线 S-14 | 写入记忆→使用权重陡升→验证差异检验触发、权重未写回见证 |

### 3.8 安全红线（19 条逐条验证）

用例编号统一为 `TC-S01-001` ~ `TC-S19-001`，与 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §8 注册的红线编号 S-01~S-19 一一对应；逐条验证方法见 [test-strategy.md](test-strategy.md) §2.2 安全红线验收表。

| 用例 ID | 对应红线 | 验证方法出处 |
|:-------|:--------|:------------|
| TC-S01-001 ~ TC-S19-001 | S-01 ~ S-19（逐条一一映射） | [test-strategy.md](test-strategy.md) §2.2 |

> **约定**：每条红线至少 1 条用例（后缀 `-001`）；如需追加用例，后缀递增（`-002`、`-003`…）。红线编号新增时（如 S-20~S-22 激活），用例编号同步扩展，不得跳号。

### 3.9 迁移与回滚（补充）

| ID | 前置 | 步骤 | 输入 | 预期输出 |
|:---|:-----|:----|:----|:--------|
| TC-A07-001 | 旧版 schema（上一版本） | `kairos db migrate` 执行正向迁移（竖切功能 A-07） | 迁移命令 | 迁移成功；`schema_version` 更新；既有数据无损（含 occurred_at 双时态与版本链字段） |

## §4 测试数据准备

### 种子数据

```python
# test_data/seeds.py — 测试启动时自动加载
seeds = [
    {"path": "kairos://test/core/greeting", "content": "hello world", "contract": "permanent"},
    {"path": "kairos://test/core/farewell", "content": "goodbye", "contract": "ondemand"},
    {"path": "kairos://test/domain/topic_a", "content": "AI memory systems", "contract": "environmental", "vad": {"v":0.6,"a":0.4,"d":0.7}},
    {"path": "kairos://test/domain/topic_b", "content": "spaced repetition", "contract": "temporary"},
]
```

### 夹具

- `MockStorageBackend` — 内存存储，测试后自动清理
- `FrozenClock` — 固定时间戳，确保遗忘曲线可预测
- `NullEmbedding` — 返回固定向量，消除 Embedding 模型引入的不确定性

## §5 缺陷跟踪

- **追踪工具**：GitHub Issues（或本地 TODO 文件）
- **标签体系**：`bug/p0`（阻塞）、`bug/p1`（严重）、`bug/p2`（轻微）、`test-missing`（缺用例）
- **流转**：发现 → 开 Issue（含测试用例/日志/环境） → 修复 → 对应测试通过 → 关闭
- **单人简化**：你自己就是 PM/开发/测试，发现即修，修完即关
