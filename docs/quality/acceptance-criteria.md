## 一、Code Debt 完成条件

### D-301 逻辑-因果轴完整落地

**验收条件**（全部满足即视为完成）：
1. 因果链完整性检查器：输入一条记忆 ID，可输出该记忆所属因果链的完整节点列表
2. 执行流断裂检测器：程序性记忆的执行步骤序列出现断点时，标记 `execution_flow_broken`
3. 节律记忆时间索引：周期性事件的后续触发预测与实际情况的偏差 ≤ 20%（对短周期事件如日周期的 20% ≈ 4.8h——此时偏差上限实用意义有限，短周期事件以 ±2h 为补充判断）
4. 时间贴现加权：检索排序中物理时间和逻辑-因果时间的加权公式按配置执行

### D-302 动态身份增强

**验收条件**：
1. 身份注册表定期（每 N 周期）适配性审查执行成功
2. 核心/外围区分生效：外围身份可降级（is_identity→false），核心身份不可降级
3. 身份记忆降级门槛由「宪法修订端口」降至「元认知层+宪法解释层联合审批」
4. 所有身份调整事件写入审计日志

### D-303 能力转化状态机

**验收条件**：
1. procedural::nascent → consolidated → degraded 状态机可被代码追踪
2. 状态转换触发条件（验证计数 + 冷却周期）按配置执行
3. 状态转换事件写入使用事件总线
4. 长期不用的程序记忆可退回至 `degraded` 状态（需要 WM 检索才能重新执行）

### D-304 定向遗忘机制（已闭环，见 DC-027）

**验收条件**：
1. 通过 CLI/REST API 执行定向遗忘 → 标记路径不可检索
2. 定向遗忘的数据仍保留在存储层（可恢复）
3. 所有定向遗忘操作写入审计日志（含操作者/时间/原因/HMAC）
4. 通过宪法解释层的定向遗忘审查器授权（非自授权）
5. 定向遗忘不逃逸 S-10（不被遗忘的见证仍豁免）

### D-305 外部校准源充分性建模

**验收条件**：
1. 校准源可靠性评估函数实现（输入：校准信号时间序列 → 输出：可靠性分数）
2. 充分性判据函数实现（当前覆盖维度 vs 所需覆盖维度的差距量化）
3. 充分性不足时发出主动告警（而非仅被动降级）
4. 单 Provider 降级按加权规则执行

### D-306 四轴完整度量函数

**验收条件**：
1. 反例覆盖度监测器：跟踪已覆盖推理空间边界 / 总边界
2. 路径禁区标注密度监测器：已标注死胡同路径 / 总探索路径
3. 组合约束网络连通性监测器：约束间可达路径数 / 最大可能数
4. 三项指标可通过 API 查询

## 三、时序基准参数（[rl-weight-spec.md](../specification/rl-weight-spec.md) §权重优化器实现）

> 以下参数定义架构文档 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §10 中基准测试的配置。架构文档中不再保留此参数表，以此处为准。

| 参数 | 默认值 | 说明 |
|:-----|:------|:-----|
| `KAIROS_BENCHMARK_TEMPORAL_GRANULARITY` | `day` | observation 窗口粒度（`day`/`week`/`month`） |
| `KAIROS_BENCHMARK_OFF_BY_ONE_SCORE` | 0.80 | off-by-one 容忍得分 |
| `KAIROS_BENCHMARK_OFF_BY_TWO_SCORE` | 0.50 | off-by-two 容忍得分 |

| `KAIROS_BENCHMARK_TASK_SCORE_WEIGHTS` | `[0.40, 0.30, 0.20, 0.10]` | 四维度权重向量 |
