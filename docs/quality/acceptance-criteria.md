## 一、Code Debt 完成条件

### D-301 逻辑-因果轴完整落地

**验收条件**（全部满足即视为完成）：
1. 因果链完整性检查器：输入一条记忆 ID，可输出该记忆所属因果链的完整节点列表
2. 执行流断裂检测器：程序性记忆的执行步骤序列出现断点时，标记 `execution_flow_broken`
3. 节律记忆时间索引：周期性事件的后续触发预测与实际情况的偏差 ≤ 20%（对短周期事件如日周期的 20% ≈ 4.8h——此时偏差上限实用意义有限，短周期事件以 ±2h 为补充判断——±2h 判据适用于短周期事件（时间跨度 ≤24h），长周期事件以偏差率判据为准）
4. 时间贴现加权：检索排序中物理时间和逻辑-因果时间的加权公式按配置执行

### D-302 动态身份增强

**验收条件**：
1. 身份注册表定期（每 N 周期，N=30（可配置））适配性审查执行成功
2. 核心/外围区分生效：外围身份可降级（is_identity→false），核心身份不可降级
3. 身份记忆降级门槛由「宪法修订端口」降至「元认知层+宪法解释层联合审批」
4. 所有身份调整事件写入审计日志

### D-303 能力转化状态机

**验收条件**：
1. procedural::nascent → consolidated → degraded 状态机可被代码追踪
2. 状态转换触发条件（验证计数 + 冷却周期）按配置执行
3. 状态转换事件写入使用事件总线
4. 长期不用的程序记忆可退回至 `degraded` 状态（需要 WM 检索才能重新执行）

### D-304 定向遗忘机制（已闭环，见 DC-027）

**验收条件**：
1. 通过 CLI/REST API 执行定向遗忘 → 标记路径不可检索
2. 定向遗忘的数据仍保留在存储层（可恢复）
3. 所有定向遗忘操作写入审计日志（含操作者/时间/原因/HMAC）
4. 通过宪法解释层的定向遗忘审查器授权（非自授权）
5. 定向遗忘不逃逸 S-10（不被遗忘的见证仍豁免）

### D-305 外部校准源充分性建模

**验收条件**：
1. 校准源可靠性评估函数实现（输入：校准信号时间序列 → 输出：可靠性分数）
2. 充分性判据函数实现（当前覆盖维度 vs 所需覆盖维度的差距量化）
3. 充分性不足时发出主动告警（而非仅被动降级）
4. 单 Provider 降级按加权规则执行

### D-306 四轴完整度量函数

**验收条件**：
1. 反例覆盖度监测器：跟踪已覆盖推理空间边界 / 总边界
2. 路径禁区标注密度监测器：已标注死胡同路径 / 总探索路径
3. 组合约束网络连通性监测器：约束间可达路径数 / 最大可能数
4. 三项指标可通过 API 查询

## 一a、记忆质量评估指标（v1.1+ 设计目标）

> **外部理念吸收注记**：本节指标吸收自外部对记忆系统的评估框架（2026-07）——评价记忆系统不能只看召回率，至少需覆盖相关性、**过时调用率**、**任务成功率**与成本四项。Kairos 已有相关性（语义检索判据 §二）与成本（benchmark-plan 性能指标）维度，本节补齐缺口的两项「学习效果」指标。
>
> **定位声明**：以下指标为 v1.1+ 设计目标，v0.1.0 不设硬性阈值（同架构 §10.5 占位声明口径——指标值均为理论推导，代码启动后经基准测试验证后晋升）。数据基础在 v0.1.0 已具备（freshness 状态 + usage_events 表 + 检索日志），指标落地不要求新表。

### 过时调用率（Stale Call Rate）

**定义**：检索结果中被遗忘调度器/freshness.py 标记为 `stale` 或 `expired`（或 fact_freshness 中 `status ∈ {stale, expired}`）的记忆，被选中进入最终输出（WM 激活/上下文注入）的比例。分母为全部被选中进入输出的检索结果数，分子为其中过时者数。

**语义**：回答「记忆系统会不会把已经过时的经验当成有效经验使用」——视频案例：处理 2026 年网站时检索到 2024 年但文字高度相似的流程，比较新的弱相似经验更危险。过时调用率是「检索质量 × 遗忘质量」的联合失效面，单看召回率无法暴露。

**v0.1.0 数据基础**：`memories.status`（active/stale/archived）+ `fact_freshness.status` + `usage_events`（检索-选择-结果三元组）。指标计算为离线聚合（Deep 模式日频），不进入实时检索路径。

**阈值（设计目标）**：过时调用率 > 20% 触发质量告警（warning）；> 40% 触发治理面审查（critical）。具体值经首轮基准验证后校准。

### 任务成功率改善（Task Success Rate Improvement）

**定义**：在集成场景（外部 Agent 如 Hermes 使用 Kairos 记忆完成真实任务）下，启用记忆检索相比不启用记忆检索的任务成功率的净改善幅度。

**语义**：回答「记忆让 Agent 变强了没有」——对应视频第1集「学习 = 能力发生可测量的改善」。改善须经**反事实检验**成立才算数（见 [test-strategy.md](test-strategy.md) §2.7）：拿走历史上下文、仅保留系统声称已学到的内容时，改善仍然存在，而非仅靠上下文续写。

**测量方法**：三态对比（完整上下文 / 仅检索记忆 / 无记忆）的 A/B 测试，用例模式见 [test-strategy.md](test-strategy.md) §2.7。任务成功率由外部 Agent 侧反馈回传（Hermes Memory Provider 集成层）。

**阈值（设计目标）**：记忆态相对无记忆态的成功率净改善 ≥ 10% 判定「记忆有效」；反事实检验中「仅检索记忆」态相对「无记忆」态无显著改善时，判定为伪持续学习（上下文续写型），触发记忆质量审查。

### 记忆系统成熟度五问评估清单（外部理念吸收 0.0.41）

> **外部理念吸收注记**：评估记忆系统不能只看「检索准不准」——还需回答「系统作为记忆体的成熟度」：原始事实是否还在、加工产物能否回溯、读写决策是否显式、审计是否可查、回放是否可复现。以下五问作为 v0.1.0 验收检查项，全部通过视为记忆系统成熟度合格。

| # | 评估问题 | 验收判据 |
|:--|:--|:--|
| ① | **原始事实是否保留？** | 原始轮次/未加工内容在升华、压缩、改写后仍可回溯——`journal_entries` 保留原始内容、`memory_versions` 快照可回滚、升华产物 provenance 链完整（原始事实 → 加工产物可溯源） |
| ② | **视图是否可回溯？** | 派生视图（摘要、embedding、关系边、kNN 近邻）可回溯至生成源记忆——`compression_trail` / `derived_from` 溯源链可查；重建后结果一致（索引为派生视图可重建，见 detailed-design §2 写入管线设计） |
| ③ | **读写决策是否显式？** | 每次写入/修改/遗忘/压缩决策显式可查（谁、何时、为何）——`audit_log` + `memory_states` + `usage_events` 覆盖决策轨迹，无静默写入路径 |
| ④ | **审计是否可查？** | 审计链 HMAC 完整性可验证——安全红线 S-01~S-19 单元测试通过 + 审计链连续性校验通过 |
| ⑤ | **回放是否可复现？** | 同一输入序列的回放结果可复现——恢复契约六属性（见 detailed-design §10.5）验收通过；基准测试可复现（见 [benchmark-plan.md](benchmark-plan.md) §四 统计方法） |
