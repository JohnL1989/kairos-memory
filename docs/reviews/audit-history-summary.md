# Kairos 审计历史摘要

> **定位（0.0.18 决策）**：本文为全库审计历史的**唯一归档**——各轮审计的问题数、处置批次与关键产物索引。审计报告为过程产物：问题闭环后原报告删除、处置要点登记于此,不再保留完整问题清单。决策编号 D-01~D-27 的权威定义已迁移至 [adr.md](../governance/adr.md)「审计决策迁移」节,本文不重复。
>
> **归档机制（0.0.18 起，0.0.29 修正）**：后续每轮审计闭环后,将问题数/处置批次/关键决策登记于本文 §一 汇总表,删除原审计报告——审计报告不再长期留存。
>
> **归档衔接规则（0.0.29 补充，C-04 闭环）**：**未闭环项存在时原报告不删除**——仅当该轮全部问题（含排期遗留项）闭环后,原报告方可按 0.0.18 机制归档。同时每轮登记时须在汇总表保留「未闭环项标题级清单」（如「余 M-02/M-08/M-09…按 0.0.28 排期」）,标题级清单不依赖原报告存在——堵「归档即丢失处置上下文」漏洞（round9 的 M-02/L-01~L-03 处置上下文因原报告删除而丢失的教训）。
