# Kairos 项目计划

> **代码状态声明**：Kairos 为全面重新设计的系统，全系统尚无可运行的完整 Kairos 发行版。以下所有 Phase 里程碑为架构设计就绪状态下的计划——实际启动时间线待正式代码库建立后确定。
>
> **定位**：从草稿完善阶段到 v0.1.0 可运行的里程碑分解。当前 v0.1.0 为草稿完善阶段版本，代码尚未启动，本文为执行路线图。

---

## 一、竖切范围（v0.1.0-slice）

竖切以架构 §0.8 最小系统为基线，2026-07-31 决策固化：

| 维度 | 竖切范围 |
|:-----|:--------|
| 组件 | 统一 LTM + 路径空间 + 三信号混合检索 + 单曲线指数衰减遗忘（含潜伏势能重估）+ 身份注册表（构造论）+ 基础审计日志 |
| 事件总线 | 4 类事件：use_event / calibration_signal / degradation_switch / latent_trigger（架构 §10.10） |
| 身份模型 | 构造论：初始赋予（见证锚定写入触发）+ 叙事驱动双向更新（认知基础 D.2 / 架构 §5.2） |
| 存储后端 | SQLite + sqlite-vec（首迭代）；PostgreSQL + pgvector 竖切验收后适配（ADR-001） |
| 功能/表/端点 | feature-list 竖切标注（约 23 项功能）；data-model 竖切表子集（15 张，清单见 [slice-implementation-guide](../development/slice-implementation-guide.md)）；api-spec 竖切端点（REST 21 + CLI 15） |
| 时间过滤基础窗口 | `KAIROS_TIME_FILTER_ENABLED` + `occurred_at` 可空加列（D-323）；竖切内第 5 周（W05）里程碑交付基础窗口，过滤执行待 v1.1/竖切扩展——「W5」此处为里程碑周次，与功能编号 W-05（关系标注）、竖切组件序号不混用 |

## 二、里程碑（周数按单人全时开发估算，实际以进度为准）

### Phase 0：基建搭建（第 1–2 周）

| 周 | 里程碑 | 交付物 | 验证 |
|:--|:------|:-------|:-----|
| W1 | 项目骨架 | pyproject + uv 环境、CLI 入口（Click/Typer）、配置加载、git 仓库初始化、`scripts/doc-audit.py` 接入 | `kairos --version`；doc-audit 全绿 |
| W2 | 数据库与 CI | SQLite 初始化 + schema 迁移（竖切表子集 15 张，清单见 slice-implementation-guide）、pytest/ruff/mypy 管线 | 迁移可回滚；CI 通过 |

### Phase 1：核心存储与检索（第 3–6 周）

| 周 | 里程碑 | 交付物 | 验证 |
|:--|:------|:-------|:-----|
| W3 | 记忆 CRUD + 双副本 | memories 写入/读取/更新/软删除；witness_anchor + usage_weight 分离；S-14 隔离防线 | 单元测试 ≥80%；S-14 单测 |
| W4 | 路径空间 + 事件总线 | `kairos://` 前缀索引与树状浏览；events 表 4 类事件发布/订阅/背压/优先级 | S-04 路径隔离测试；事件集成测试 |
| W5 | 三信号混合检索 | 语义（sqlite-vec）+ BM25（FTS5）+ 实体加成（简化）三信号融合（0.50/0.35/0.15）；时间感知检索基础窗口（occurred_at 落列） | 1 万条基准：语义检索 P50 ≤100ms |
| W6 | 遗忘 + 潜伏势能 | 单曲线指数衰减、潜伏势能重估（latent_trigger 事件）、复兴加速 | TC-F01~F03 通过 |

> **检索权重口径注记**：三信号（语义/BM25/实体）为候选域内融合权重（架构 §7.3a）；检索扩展链路权重为四链路 0.50/0.20/0.10/0.20（架构 §5.2）——两套权重作用于检索管线不同阶段，不叠加。

### Phase ↔ 验收 ↔ 门禁对照（Marvis 建议 R-10）

> 每 Phase 的完成判定——交付物 → 验收标准 → 门禁/E2E 覆盖。使里程碑有明确、可核验的完成判定。

| Phase | 交付物 | 验收标准（acceptance-criteria） | 门禁/E2E 覆盖 |
|:-----|:------|:-------------------------------|:-------------|
| **Phase 0 基建** | 项目骨架、DB 迁移、CI | §〇 竖切验收（schema 迁移可回滚项） | `scripts/doc-audit.py` 全绿（18+14a）；迁移用例 TC-A07-001~003（test-plan §3.9） |
| **Phase 1 核心存储与检索** | CRUD+双副本、路径空间+事件总线、三信号检索、遗忘+潜伏势能 | §〇 竖切验收（检索/写入/遗忘判据）+ §二 非功能检查 | E2E-01/02/06/07；TC-W01~04/R01~03/F01~03（test-plan §3） |
| **Phase 2 身份与治理闭环** | 身份注册表、校准+降级+审计 | §〇 竖切验收（校准/降级/审计判据）+ G-03 v0.1.0 判据 | E2E-04/05/06/08；TC-CAL01~04；S-10/S-11/S-14 红线单测 |
| **Phase 3 集成验证与验收** | 基准、文档对齐、竖切验收 | §〇 竖切验收全项 + §二 发布检查项 | E2E 全 9 条（竖切 7/9 口径见 test-plan §2 注记）；19 红线；`deep-audit.py` 全绿 |

**判定顺序**：Phase N 完成判定 = 本表验收标准全满足 + 门禁/E2E 覆盖全绿，方可进入 Phase N+1。

## 三、风险与缓冲

| 风险 | 概率 | 影响 | 缓解 |
|:----|:----:|:----:|:-----|
| pgvector 性能不达预期 | 中 | 检索延迟超限 | 竖切以 SQLite 开发，PG 适配时准备 HNSW 参数调优 |
| LLM 嵌入依赖不可用 | 低 | 语义检索中断 | 本地嵌入模型 BGE-M3 备选（轻量模式已用） |
| 轻量模式 SQLite 容量瓶颈 | 低 | 10 万条上限 | 竖切验收后切换标准模式 |
| 跨层协调复杂度超限 | 低 | 维护成本增加 | 绝对上限 10 条协议控制 |
| 事件类型注册门禁滞后 | 中 | 竖切外组件启用时事件扩展失控 | 类型注册门禁（架构 §10.6）随首迭代 4 类事件一并实现 |
| 构造论初始赋予与事件驱动的操作间隙 | 低 | 身份建构在审计间隙延迟 | 事件触发额外扫描补偿（架构 §1.8）；G-03 追踪 |
