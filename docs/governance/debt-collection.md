# Kairos 认知-工程差距分析

> **本文档不是 TODO 清单，而是「认知意图 vs 工程交付」之间已知差距的显式管理。**
>
> 认知基础文档定义了一个完整的认知模型——多维评分系统（正交性假设）、多重记忆、P1–P6 设计原则、六
> 级辞典式排序链、分域真理观。架构文档在该模型的部分约束下做工程实现。当两者之间产
> 生系统性偏离时，这些偏离被记录为本差距分析，而非被认知层的光环所掩盖。
>

> | 段 | 内容 | 回答的问题 |

> | 升级触发条件 | 什么运行指标表明成本已不可接受 | 什么时候应该升级 |
> | 历史背景 | 此简化被接受时的版本、条件、替代方案评估 | 为什么当初这么做 |

## 一、架构设计间隙（文档级可修）

以下项在认知层有完整定义，架构层当前以简化形态承载。修改架构文档即可缩小差距。

### D-001 身份面正交治理（谱系：认知基础 [cognitive-foundation.md](../foundation/cognitive-foundation.md) §2.1 → 架构 §1/§3.3）

| 段 | 内容 |
|:--|:-----|
| **认知意图** | 身份面应是始终在线的主动审查官，独立于策略层运行，以否决权正交模型介入排序产出（认知基础 [cognitive-foundation.md](../foundation/cognitive-foundation.md) §2.1 身份面声明） |
| **工程简化** | v0.1.0 已按架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §1.8 采用预提交总线 + 身份总线监听器 + 否决裁决器三组件模型（替代原三点分布式检查——本节为 Phase 1 历史简化记录）。身份注册表（§5.2）+ 叙事连贯性检测器（架构 §2.2）仍为否决权的数据源与触发源；否决裁决器作为预提交总线消费端组件，在存储层写入路径上检查 `veto_event`——非经预提交总线的裁决产出，存储层拒绝写入（不可绕过） |
| **可接受成本** | (1) 策略层可通过不调用身份查询来绕过审查——虽然当前设计策略层「应该」调用，但没有机制强制；(2) 否决权的可靠性依赖三个结构单元的协同——任一元降级时否决权降级 |
| **升级触发条件** | 已无触发布线升级对象——预提交总线模型已纳入 v0.1.0 交付（架构 §1.8 权威）。原条件（(1) 策略层未调用身份查询的裁决产出比例 > 1% 连续 ≥3 周期；(2) 身份注册表 HKLA 中 `narrative_coherence_score` 在无外部校准时下降速率 > 0.02/周期）所针对的「主动查询可被绕过」缺口，已由否决裁决器的不可绕过性保证替代 |
| **历史背景** | v0.1.0 早期设计因事件总线基础设施尚未经历长时间运行验证，曾采用三点式分布式实现以保证最低可用性。0.0.11/0.0.14 批次架构决策将预提交总线模型写入 v0.1.0 交付（架构 §1.2/§1.8 权威，替代三点分布式检查）；本节保留为 Phase 1 历史简化记录 |

### D-002 工作记忆层的语义绑定能力（谱系：认知基础 [cognitive-foundation.md](../foundation/cognitive-foundation.md) §1.3 → 架构 §6）

| 段 | 内容 |
|:--|:-----|
| **认知意图** | WM 是认知加工的核心工作区——需要将从不同源（感知、检索、预测）的信息「绑定」为统一的认知表征（认知基础 [cognitive-foundation.md](../foundation/cognitive-foundation.md) §1.3.2 WM 四要素：维护/操作/整合/绑定） |
| **工程简化** | v0.1.0 WM 的多路径结果集做分类级融合（交集→直接入 WM，独有→缓冲池），不做语义级绑定。Phase 1 已新增本地绑定器（Local Binder）作为 WM 子组件，但绑定器的输出 `WorkRepresentation` 绑定到 `request_id`——检索完成即销毁，不支持跨请求的工作表征维持 |
| **可接受成本** | (1) 跨请求的认知连续性（如多个顺序检索请求之间需要延续同一个工作表征）当前不可实现；(2) 绑定器依赖多个输入源——任一输入源故障时降级输出（标记 `binding_degraded`），可能产生不完整的绑定 |
| **升级触发条件** | 元认知层检测到连续 ≥5 个请求的报告 `binding_degraded` 比例 > 20% → 触发绑定器输入源可用性审查 |
| **历史背景** | Phase 1 的本地绑定器为最小可行实现——绑定到 `request_id` 使其不改变现有槽位置换逻辑也不增加持久化负担。跨请求绑定需额外的 WM 生命周期管理（v1.1+） |

### D-003 注意力调度器制衡规则谱系（谱系：认知基础 §D.7 → 架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §9）

| 段 | 内容 |
|:--|:-----|
| **认知意图** | 注意力的前置制衡应是主动的、系统性的约束，防止注意力分配陷入自利循环（认知基础 D.7 三项约束检查 + 熵过低防御） |
| **工程简化** | v0.1.0 从三项制衡（身份漂移防御、多样性阈值保护、重复路径探索）扩展为四项（+ 系统性熵过低防御，Phase 1）。制衡规则已定义优先级叠加逻辑，但制衡注入幅度由审计庭周期性审核（事后），而非运行时自适应调节（事前） |
| **可接受成本** | 制衡注入幅度在两次审计周期之间是固定值——如果运行环境在周期内发生剧烈变化（如新语义域突然爆发），制衡可能幅度不足或过度 |
| **升级触发条件** | 审计庭连续 ≥2 周期报告的「制衡注入幅度修正请求」数 > 3 → 触发自适应调幅机制的设计启动（v1.1+） |
| **历史背景** | 事前自适应调幅需要在线学习模型——v0.1.0 不做在线学习以降低系统复杂性。固定幅度 + 周期审计被评估为最低可行制衡模型 |

### D-004 WM 本地绑定器容量与降级（谱系：架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §6 — Phase 1 新增）

| 段 | 内容 |
|:--|:-----|
| **认知意图** | 本地绑定器应将多路径结果集、WM调度预处理器输出、注意力分配结果同步绑定为统一工作表征 |
| **工程简化** | Phase 1 实现为同步绑定——每次检索结果到达后立即执行，不延迟。绑定器在输入源故障时使用已有子组件输出降级，不等待故障输入源 |
| **可接受成本** | (1) 异步绑定（等待所有输入源就位后再绑定）可能产生更高品质的 WRep，但当前同步模式不引入等待延迟；(2) 绑定器不跨请求维持状态 |
| **升级触发条件** | 元认知层检测到标记 `binding_degraded` 的 WRep 中，因缺失特定输入源导致的裁决质量下降事件持续 > 5% → 评估输入源的冗余设计 |
| **历史背景** | Phase 1 新增。不做异步绑定以保持 WM 的响应时间常数——异步绑定需要额外的等待周期管理，属于 v1.1+ 优化方向 |

### D-005 图式的双重性（组织原理vs偏差来源）未在架构中统一管理

> **状态（D-03 拆分）**：文档级已闭环——认知层修复已写入认知基础/架构文档（详见 §5.4）；工程级待实现——本条目描述的架构简化与升级触发条件仍为 v1.1 待办。


| 段 | 内容 |
|:--|:-----|
| **认知意图** | 图式在认知基础中既是结构性记忆的组织原理（路径空间骨架），又是认知偏差的来源（自我证实/信息同化）。认知层预期系统在工程实现中区分这两种角色，在路径空间中以不同机制分别管理 |
| **工程简化** | 当前路径空间实现将图式单一化为异构路径之间的共享骨架索引（邻接关系标签），未区分图式的「组织」职能（主动构建）与「偏差」职能（信息过滤）。图式双重性未被架构显式管理 |
| **可接受成本** | (1) 图式的偏差放大效应不可被隔离或衰减——当图式作为骨架被激活时，其同化偏差同步增强；(2) 无法在架构层观测图式何时从「组织原理」滑向「自我证实循环」 |
| **升级触发条件** | 元认知层检测到 ≥3 次「路径空间拓扑查询返回结果中自我同化率 > 阈值」且关联的图式同时是当前骨架路径的参与者 → 触发图式双重性分治设计 |
| **历史背景** | 当前周期中未归入任何已修复项。此矛盾在认知基础中以隐性方式存在，架构首次将其识别为需要显式管理的结构性矛盾 |

### D-006 时序优先与值优先在排序链中的混用未定义适用场景规则

> **状态（0.0.32 评估）**：v0.1.0 已覆盖——适用场景规则表已写入架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §3.3（§5.4 文档级闭环），辞典式裁决器为 v0.1.0 核心交付组件（§3.0 交付范围），规则表随排序链实现一并落地，不构成独立债务。升级触发条件随运行数据监测（审计庭「排序结果不可解释」事件统计）。


| 段 | 内容 |
|:--|:-----|
| **认知意图** | 认知基础定义六级辞典式排序链，其中时序维度（时间贴现/使用频率）与值维度（多轴价值评估）具有不同的排序语义。认知层预期每种排序优先策略在架构中有显式的适用场景规则 |
| **工程简化** | 当前排序链（[architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §3.3 辞典式裁决器）将时序降权与值降权混用在同一排序流程中——时序维度作为排序键层级之一，值维度作为另一层级，但未定义何种场景下时序应优先于值（或反之）的原则性判据 |
| **可接受成本** | (1) 排序结果在边缘场景中不可解释——无法追溯「此时序优先于此值」的决策依据；(2) 适用场景边界模糊导致不同调度周期之间的排序偏好不一致 |
| **升级触发条件** | 审计庭连续 ≥2 周期报告的「排序结果不可解释」事件数 > 5 → 触发排序优先场景规则的设计 |
| **历史背景** | v0.1.0 的排序链设计优先确保基本功能可运行，未深入定义优先级混用规则。属于认知基础与架构之间的定义间距 |

### D-007 记忆与学习的工程边界（抽象萃取产出影响行为策略时边界崩塌）

> **状态（0.0.32 评估）**：v0.1.0 已部分覆盖——架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §3.2 调节器已含「抽象萃取边界门禁探针」（P2 级补偿：strategy→behavior 产出连续 N=3 次影响调度器行为时自动触发「学习-记忆边界审查」标记，审计庭下一周期审查，可配置）。完整行为验证闸门（萃取产出经验证后才写入策略层）仍为 v1.1 目标——探针提供边界跨越的可观测性，不阻塞策略→behavior 正常路径。


| 段 | 内容 |
|:--|:-----|
| **认知意图** | 认知基础区分记忆（信息的维持/检索）与学习（从记忆中抽象萃取并改变行为策略）。边界处应有闸门控制：抽象萃取产出的策略更新应经过行为验证再写入策略层，避免未经验证的抽象直接改变行为 |
| **工程简化** | 当前架构的元认知层（[architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §2.2）的抽象萃取产出直接写入程序记忆和策略提炼旁路（§6），未经过行为验证闸门。记忆与学习的工程边界处于「开放通道」状态 |
| **可接受成本** | (1) 未经验证的抽象萃取产出可能将错误模式固化到策略层；(2) 抽象萃取的「过度泛化」错误无验证屏障——认知层的「学习应该谨慎」意图在工程层未实现 |
| **升级触发条件** | 审计庭检测到 ≥2 次「抽象萃取产出被后续外部校准反向修正」的实例 → 触发边界闸门设计 |
| **历史背景** | v0.1.0 的策略提炼旁路在设计上优先保证抽象萃取的产出现实可用性，边界闸门被评估为 Phase 2 新增。本争议在评估中被识别为需要显式管理的结构性矛盾 |

### D-008 编码特异性原则→路径空间映射丢失了VAD/任务目标等非路径维度

> **状态（0.0.32 评估）**：v0.1.0 已部分覆盖——`encoding_context` 字段补偿机制已写入架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §5.2（缺失维度在编码阶段被元数据字段保留，可通过筛选查询补偿），随存储层交付。完整多维路径索引（VAD/任务语义/环境上下文入索引维度）为 v1.1 真实升级——升级触发条件（检索结果校准修正率 ≥5% 连续 3 周期）随运行数据监测。


| 段 | 内容 |
|:--|:-----|
| **认知意图** | 编码特异性原则（Tulving）要求检索线索与编码上下文匹配。认知基础路径空间在理论上应将编码的全部维度（含VAD情感维度、任务目标、环境上下文）映射为路径索引维度 |
| **工程简化** | 当前路径空间实现（[architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §4.2/§5.1）以邻接关系标签和路径本体维度作为映射维度，VAD（效价/唤醒/支配度）、任务目标语义、环境上下文的路径索引维度缺失——编码特异性原则的实际覆盖范围小于认知意图 |
| **可接受成本** | (1) 依赖VAD/任务目标编码的记忆在检索时可能被不充分激活——查询未包含VAD维度线索时，无关路径可能被激活；(2) 跨任务（不同任务目标）的路径检索结果不稳定 |
| **升级触发条件** | 元认知层检测到 ≥5% 的检索结果中需要外部校准结果参与调整排序（即路径空间检索结果的校准修正率过高）连续 ≥3 周期 → 触发路径空间维度审查 |
| **历史背景** | 当前周期中未归入任何已修复项。路径空间设计以图论可行性为优先，非路径维度的映射属于 Phase 1 简化的隐含成本 |

### D-009 身份面否决面自身崩溃无容错设计（总线监听器崩溃时所有写入被拒绝）

> **状态（0.0.32 评估）**：v0.1.0 已覆盖——容错设计已写入架构 [architecture-v0.1.0.md](../foundation/architecture-v0.1.0.md) §1.8 并纳入 v0.1.0 交付：看门狗计时器（5s）+ degraded 模式（放行但标记 `identity_check_deferred`）+ `IDENTITY_BYPASS` 标记，随身份总线监听器实现一并落地，不构成独立债务。


| 段 | 内容 |
|:--|:-----|
| **认知意图** | 身份面作为正交治理面，其否决权机制应有自身的容错设计——监听器或总线的单点故障不应导致整个系统的写入被拒绝。认知基础的「正交治理」承诺内含自身的治理可靠性保障 |
| **工程简化** | 当前身份总线监听器设计（架构 §1.8 方案）采用 fail-selective 三态模型——warmup→active（fail-closed）→degraded（放行但标记）。但 fail-closed 状态在监听器自身崩溃时，「拒绝所有写入」的行为与身份面的否决权正交性意图冲突。未定义「瓶颈自身崩溃」时的熔断与恢复路径 |
| **可接受成本** | (1) 监听器非预期崩溃时，系统陷入「全部写入被拒」的死锁状态——除非人工介入重置；(2) 熔断机制（监听器自我诊断→自动切入 degraded 模式）的设计缺失使身份面自身成为系统的可靠性单点 |
| **升级触发条件** | （本项为设计级矛盾，升级触发条件为设计交付标准——架构评审中若 路径空间/排序链/记忆存储 等任何子系统提出「身份面故障导致本子系统写入被拒」的事件 ≥1 次，应优先解决）|
